% ABSTRACT
% =========================================================
\begin{abstract}
Software engineering increasingly places an LLM at the front of an analysis
pipeline, translating a natural-language artefact into a structured input that
downstream tooling consumes as if it were valid. Such a translator is only as
trustworthy as its worst output, yet it is typically assessed by average-case
accuracy. We study this problem in a concrete setting --- turning a proposed
requirement into a bounded capacity intervention on a microservice architecture,
so that its workload can be projected before the feature exists --- and argue
that generator \emph{capability} and output \emph{validity} are separable
properties, of which only the second can be guaranteed. We formalise the
translation layer's guardrail as a total, deterministic projection operator and
prove it maps \emph{every} LLM proposal, adversarial or malformed, to a
structurally valid intervention (Proposition~\ref{prop:soundness}). Replicating
the benchmark across two vendors shows why the proof carries operational weight:
moving from a lite-tier proprietary model to an open-weight $117$B model reduces
magnitude error $25{\times}$ ($844.6\%\!\to\!33.6\%$) yet leaves gateway
misdirection at $92\%$ and service hallucination at $86\%$. Capability buys
semantic plausibility, not respect for topological constraints. Adversarial sets
confirm the guards are load-bearing ($18/18$ gateway corrections, $33/36$ clamp
activations), and porting the verifier to a second system exposed a defect
violating the proposition itself --- invisible to single-system validation.
Downstream, a protocol built to be able to fail finds that the standard RCA
benchmark cannot support capacity evaluation at all ($R^2 = 0.003$ versus $0.30$
on a production trace), and separates the two causal commitments usually defended
together: graph propagation earns its place ($85\%$ of edges), the $do$-operator
does not, for a structural reason we characterise.
\end{abstract}

% I. INTRODUCTION

\section{Introduction}
\label{sec:introduction}

A growing class of software engineering tools places an LLM at a pipeline
boundary, where it converts an informal artefact --- an issue report, a design
document, a requirement --- into a structured object that downstream automation
then treats as valid input. The LLM is not the product in these systems; it is a
translator whose output is consumed by a compiler, a solver, a simulator, or an
analysis model. This arrangement has a property that average-case evaluation
hides: the pipeline's trustworthiness is governed by the translator's
\emph{worst} output, not its mean. A single structurally invalid object can
propagate silently into a numeric verdict that an engineer then acts on.

The usual response is to improve the generator --- better prompting, a larger
model --- on the implicit assumption that validity is a byproduct of capability.
We show this assumption fails in a way that matters. Capability and validity are
separable: a substantially larger model produces far more \emph{plausible}
values while violating \emph{structural} constraints at nearly the same rate
(Section~\ref{sec:rq1-backend}). If that holds, then no realistic amount of
model improvement removes the need for a verifier, and the verifier --- not the
generator --- is where a guarantee has to live.

We study this in a setting where the structured object is sharply specified and
the stakes are concrete. Given a natural-language requirement for a feature that
does not yet exist, we translate it into a bounded capacity intervention on a
microservice dependency graph and project the resulting workload, so that a team
can judge feasibility before committing engineering effort. The setting is
useful for our purpose because validity is \emph{decidable}: an intervention is
structurally valid only if it names services present in the architecture, is
applied at an ingress node, and carries a magnitude inside physically admissible
bounds. Those are checkable predicates, which makes a soundness proof possible
where it would not be for free-form generation.

\textbf{Scope.} We bound ``new requirement'' to features approximable by an existing calibration archetype within the target system's request taxonomy (Section~\ref{sec:methodology}) --- e.g., a new promotion mechanic is treated as a variant of an existing checkout-discount archetype. A requirement matching no known archetype is out of scope for a numeric verdict; Section~\ref{sec:discussion} discusses how the implementation handles this case.

Our main contributions are:
\begin{enumerate}
    \item \textbf{A verifier for LLM-proposed interventions with a provable guarantee, shown to be load-bearing.} We formalise the guardrail as a total, deterministic projection operator $\Pi$ (Proposition~\ref{prop:soundness}) whose structural guarantees hold for \emph{every} LLM output, not merely those observed at test time, and demonstrate through purpose-built adversarial sets that the guarded constraints are ones an unguarded generator actually violates (Sections~\ref{sec:rq1}--\ref{sec:rq2}).
    \item \textbf{Evidence that model capability does not substitute for verification.} Replicating the benchmark on an open-weight $117$B model from a second vendor reduces magnitude error $25{\times}$ while leaving gateway misdirection at $92\%$ and service hallucination at $86\%$, across all four prompt categories. Capability improves semantic plausibility and leaves structural validity roughly unchanged --- so the verifier is not a stopgap awaiting better models (Section~\ref{sec:rq1-backend}).
    \item \textbf{Evidence that a proved design still requires its implementation validated elsewhere.} Porting the verifier to a second system with $14$ gateways rather than one exposed three defects invisible on the original topology --- including a hard-coded fallback that violated Proposition~\ref{prop:soundness} itself (Section~\ref{sec:rq3}).
    \item \textbf{An evaluation protocol that can return a negative answer, and a benchmark diagnosis.} A signal gate, a predictor-free baseline, and a permuted-workload negative control together establish that RCA benchmarks cannot support capacity-forecasting evaluation ($R^2 = 0.003$ against $0.30$ on a production trace), and that on data which does support it the deployed mechanism forecasts with positive skill in and out of distribution (Section~\ref{sec:rq4}).
    \item \textbf{An honest accounting of the downstream model, including what we withdraw.} We separate the two causal commitments usually defended together --- the dependency graph earns its place, the $do$-operator does not, for a structural reason we characterise in four independent tests --- and retract a memory-forecasting result from earlier work, where a MAPE of $0.15$ with skill of zero reproduces on both datasets as an artefact of reporting scale-dependent error without a predictor-free baseline (Sections~\ref{sec:rq4}--\ref{sec:rq5}).
\end{enumerate}

\section{Background and Related Work}
\label{sec:background}

Our problem sits at the intersection of a question about LLMs --- how to make an
LLM's output safe for a downstream automated consumer --- and a question about
systems --- how to project the load of a feature that has never run. We therefore
review the verification of LLM output first, since it supplies the frame, and then
the three bodies of systems work that determine what the downstream model can be.
Table~\ref{tab:positioning} summarizes how each relates to the query we target.
For the systems literature the distinguishing axis is not accuracy but
admissibility: whether a method can be evaluated at all when the subject of the
query has never run, and therefore has no telemetry of its own.

\subsection{LLMs in Software Engineering, and Their Verification}
LLMs are now applied across the software lifecycle \cite{hou2024llm4se}, including requirements elicitation and classification \cite{arora2024rellm}. Their weakness is well documented: fluent but unfaithful output \cite{ji2023hallucination}, and specifically a deficiency in deterministic planning that prompting does not repair \cite{kambhampati2024,valmeekam2023planbench}. The LLM-Modulo response is architectural rather than prompt-level: the model generates candidates and an external, sound verifier accepts or repairs them \cite{kambhampati2024,garcez2023neurosymbolic}. We adopt this separation strictly, and our multi-agent orchestration follows the ReAct paradigm of interleaved reasoning and tool-acting \cite{yao2023react,wu2023autogen}, with a self-critique pass in the spirit of Reflexion \cite{shinn2023reflexion}.

Where a verifier cannot repair a candidate, the remaining option is to abstain. Selective prediction formalizes this risk--coverage tradeoff \cite{elyaniv2010selective,geifman2017selective}, and conformal prediction supplies distribution-free guarantees on the resulting error rate \cite{vovk2005algorithmic,angelopoulos2023conformal}, including for language models \cite{quach2024conformal} and for schema-linking abstention in text-to-SQL \cite{chen2025rts}. Our Scope Gate (Section~\ref{sec:scope-gate}) instantiates this pattern for requirement admissibility.

What this literature leaves open is an empirical question about the
\emph{necessity} of the verifier rather than its design. Because reported
violation rates are almost always measured on one backend, an architectural
guardrail is open to the reading that it compensates for a weak generator and
will be obsoleted by a stronger one --- a reading under which
the LLM-Modulo separation \cite{kambhampati2024} is sound but transitional. Testing it
requires holding the task, prompts, and harness fixed while varying the
generator, and reporting the failure modes \emph{separately} rather than as a
single accuracy figure, since they need not move together.
Section~\ref{sec:rq1-backend} does this and finds they do not: across a
$117$B-parameter open-weight model and a lite-tier proprietary one, the
magnitude error differs by $25{\times}$ while the structural violation rates are
nearly equal. To our knowledge this separation of semantic from structural
failure under a controlled backend change has not been reported for
requirement-to-artefact translation.

\subsection{Performance Prediction for Microservices}
A substantial line of systems work predicts microservice performance from
telemetry. Seer \cite{gan2019seer} anticipates QoS violations from traced
execution, Sage \cite{gan2021sage} adds a causal Bayesian network for
root-cause attribution, Sinan \cite{zhang2021sinan} allocates resources under
QoS constraints, and FIRM \cite{qiu2020firm} performs fine-grained SLO-oriented
management; Autopilot \cite{rzadca2020autopilot} autoscales production workloads
at Google. Cloud configuration search --- Ernest \cite{venkataraman2016ernest},
CherryPick \cite{alipourfard2017cherrypick}, PARIS \cite{yadwadkar2017paris} --- similarly predicts performance under a \emph{configuration} change. All of these
condition on observations of the workload whose behavior they predict. A
requirement that has not been implemented supplies none, which places it outside
their evaluation protocol rather than merely at the hard end of it.

\subsection{Analytical Performance Modeling}
Software performance engineering has modeled resource contention analytically
for decades \cite{balsamo2004survey,woodside2007future}: layered queueing
networks \cite{franks2009lqn} and component models such as Palladio
\cite{becker2009palladio} predict response time from a hand-specified model of
service demands, and support what-if analysis by editing that model. This
tradition answers questions structurally similar to ours, and our
queueing-inspired latency mechanism (Section~\ref{sec:workload-propagation})
borrows its heavy-traffic intuition \cite{kingman1961}. Two differences
motivate our approach. First, these models require per-component service demands
elicited by hand, whereas our mechanisms are fit from the target system's own
telemetry. Second, a what-if edit to an analytical model carries no
identifiability semantics: it changes a parameter, but offers no account of
which counterfactual quantity is thereby estimated, which is exactly what
$do$-calculus supplies.

\subsection{From Retrospective RCA to Prospective Forecasting}
Traditional machine learning fits an association between $X$ and $Y$ within the
observed distribution, not a mechanism that survives $X$ being deliberately
changed. Pearl's SCM \cite{pearl2009causality} separates the two via the
$do$-operator: for an intervention $do(X_i = x_i^*)$ the truncated factorisation
builds the interventional distribution from the \emph{same} conditional
mechanisms with the edges into $X_i$ severed rather than conditioned on, and
Huang and Valtorta established completeness for Pearl's three rules
\cite{huang2006complete}.

Causal methods have been applied extensively to microservice diagnosis:
MicroCause \cite{meng2020microcause} infers causality over monitoring series,
CIRCA \cite{li2022circa} formulates localisation as intervention recognition,
CausIL \cite{chakraborty2023causil} builds instance-level graphs, Eadro
\cite{lee2023eadro} fuses multi-source telemetry, and BARO
\cite{nguyen2024baro} couples change-point detection with robust ranking.
Budhathoki et al.\ \cite{budhathoki2022rootcause} give the sharpest formulation,
attributing an observed outlier to upstream causes via Shapley values over a
causal graph --- the mechanism DoWhy-GCM \cite{blobaum2024dowhy,sharma2020dowhy}
exposes as \texttt{attribute\_anomalies}. Across this literature the query is
uniform: an anomaly has occurred, and the task is to rank its ancestors.

\textbf{When does the operator confer an advantage?} Only when a backdoor path
exists between the intervened variable and the outcome; absent one,
$P(Y \mid do(X)) = P(Y \mid X)$ identically and the operator is an expensive
no-op. This distinction organises the divide above. A fault is injected
\emph{into} a specific service, so RCA interventions are internal, the intervened
node has parents, and backdoor paths exist. A new customer-facing requirement
enters at the system boundary, so its intervention sits at a root node with no
incoming edges to sever. Section~\ref{sec:rq5} measures the consequences.


\subsection{Benchmarks and Statistical Methodology}
We evaluate on RCAEval \cite{pham2024rcaeval}, a public microservice benchmark providing fault-injected telemetry for both the Sock Shop and Train Ticket topologies \cite{gan2019deathstarbench}. Model comparison follows the non-parametric protocol of Demšar \cite{demsar2006}: a Friedman omnibus test over all models, and paired Wilcoxon signed-rank tests only where the omnibus test licenses post-hoc comparison. Because we conduct multiple such comparisons per system, all reported $p$-values are Holm-corrected \cite{holm1979}; because MAPE is sensitive to small denominators \cite{hyndman2006accuracy}, all comparisons are conducted on ranks and accompanied by rank-based effect sizes --- matched-pairs rank-biserial correlation $r$ and Cliff's $\delta$ \cite{cliff1993dominance} --- which are invariant to any monotone rescaling of the underlying error metric. Threats to validity are organized following Wohlin et al.\ \cite{wohlin2012experimentation}.

\section{Methodology}
\label{sec:methodology}

\textbf{Notation.} Let $\mathcal{G} = (V, E)$ denote the dependency graph, where $V = V_W \cup V_R$ partitions into workload and resource nodes. For node $j$, $PA_j$ denotes its parent set in $\mathcal{G}$ and $N_j$ its exogenous noise term.

\subsection{System Architecture Overview}
The system is a four-node LangGraph state machine, executed sequentially per requirement. The \emph{Parser Agent} (Section~\ref{sec:parser-agent}) turns text into a bounded intervention $do(X{=}x)$. The \emph{Architecture Agent} performs a breadth-first traversal from the injection gateway to determine the blast radius of affected services. The \emph{Capacity Agent} projects downstream resource consumption along two paths: a fast per-service bivariate SCM, and an accurate topology-adaptive global DAG propagating through both the cross-service workload tier and the local resource-consumption tier (Section~\ref{sec:workload-propagation}). Finally, an LLM synthesizes the projected metrics and a self-critique pass into a natural-language \texttt{FeasibilityReport}. Sections~\ref{sec:results} evaluates nodes one and three, which carry the causal and LLM machinery; node two is a deterministic graph traversal, and node four is not evaluated quantitatively.

\subsection{Parser Agent: Semantic Bridge and Three-Layer Verification}
\label{sec:parser-agent}
The Parser Agent translates natural language into a quantitative intervention vector $do(X=x)$. It follows a two-tier strategy: a deterministic keyword-similarity match against an empirical calibration table is attempted first (bypassing the LLM entirely when similarity $\geq \tau$, with $\tau = 0.6$); otherwise the LLM is invoked to propose a request type, affected services, and a bounded adjustment. The same threshold $\tau$ also controls, within the LLM branch, whether the LLM's proposed adjustment is used or zeroed (forcing the calibration anchor unmodified when match confidence is low). Since sweeping $\tau \in [0.3, 0.8]$ on the RQ3 test set left all safety metrics (PBVR, SHR, Anchor MAE) completely unchanged --- only the fast-path bypass rate shifted --- we treat $\tau$ as a cost--accuracy design parameter rather than a safety mechanism, and do not count it among the verification layers below.

In both branches, the output passes through a \textbf{three-layer symbolic verification architecture} before being returned (Fig.~\ref{fig:verification}). Following the LLM-Modulo separation of concerns \cite{kambhampati2024}, the LLM is treated strictly as a non-deterministic candidate generator $L$, and a deterministic, sound verifier enforces all safety properties independently of $L$'s reliability. The three layers are organized by their distinct mathematical purpose --- selective abstention, graph-membership enforcement, and interval projection --- rather than enumerated as a flat list, and each targets one category of failure mode we observed the unguarded LLM exhibit.

\subsubsection{Layer 1: Scope Gate (Selective Abstention)}
\label{sec:scope-gate}
The LLM branch is explicitly instructed to always select the closest-matching known request type rather than decline (Section~\ref{sec:edge-of-scope}), so after it returns a choice the Scope Gate independently decides whether that choice should be trusted at all. The gate combines four signals into a single logistic score $s(x) = P(\text{out-of-scope}\mid x)$: keyword overlap against the chosen type's own keyword list, the LLM's pick-similarity, the rule-based guess's similarity, and a structural self-declaration (\texttt{is\_customer\_facing\_feature}) elicited in the same extraction call. Two thresholds, calibrated by split-conformal prediction \cite{angelopoulos2023conformal} on 81 labeled prompts, partition the score. Below $\tau_{\text{pass}}$ the requirement proceeds normally. At or above $\tau_{\text{refuse}}$ the report node short-circuits to an explicit refusal, rather than allowing the downstream LLM to synthesize a confident verdict around a fallback number. Between the two it returns \texttt{NEEDS\_HUMAN\_REVIEW}. This layer implements \emph{selective abstention} rather than projection, which distinguishes it from Layers 2 and 3: those correct an invalid candidate, whereas this one declines to produce any. Section~\ref{sec:edge-of-scope} gives the derivation and the adversarial evidence motivating it.

\subsubsection{Layer 2: Entity Grounding (Graph-Membership Invariants)}
\label{sec:entity-grounding}
This layer enforces that every entity proposed by the LLM corresponds to a real node in the topology graph $\mathcal{G}$ --- a deterministic set-membership check with no free parameter.
\begin{itemize}
    \item \textbf{Gateway Invariance:} the injection point $do(x)$ must be applied at a node with in-degree $= 0$; if the LLM proposes an internal node, the system falls back to the nearest valid gateway and downgrades confidence to \textsc{low}. On RQ3's 50-prompt benchmark the LLM's \texttt{injection\_service} proposal was always correct (\texttt{front-end}, unanimously across 150 live calls), so the layer never fired. An 18-prompt adversarial set describing plausible backend and asynchronous work induced a non-gateway proposal on \emph{every} prompt, and the fallback corrected all $18$. This demonstrates \emph{rejection} of an invalid gateway, not \emph{disambiguation} among several valid ones, which this single-gateway topology cannot exercise (Section~\ref{sec:threats}).
    \item \textbf{Service Existence Filter:} discards any proposed \texttt{core\_services} entry that does not correspond to a real node in $\mathcal{G}$, preventing hallucinated services from propagating downstream.
\end{itemize}

\subsubsection{Layer 3: Bounded Projection $\Pi$}
\label{sec:bounded-projection}
This layer constrains how far the LLM's numeric proposal may deviate from the
calibration table, and is the only layer with hand-set thresholds. An outer clamp
holds the workload delta to $[5\%,50\%]$; an inner clamp restricts the LLM's
adjustment of the calibration anchor to $\pm10\%$, with violations falling back to
the unadjusted anchor. The outer bound sits at a knee: replaying 300 raw
unguarded proposals (reaching $50{,}000\%$) against candidate bounds, tightening
to $[10,30]$ nearly doubles the flagged-violation rate ($26.3\%\to47.0\%$) while
loosening to $[1,100]$ barely helps ($26.3\%\to21.3\%$), so the excluded tail is
pathological rather than borderline. The inner clamp never fires on benign
prompts --- including with its instruction removed from the prompt, ruling out
circularity --- but a 12-prompt manipulation set pushed raw adjustments to
$+500\%$ and triggered it on $33/36$ attempts. It is inert in normal operation
and the only barrier in adversarial operation.

\textbf{Formalisation.} Let $L : \Sigma^* \to T \times \mathbb{R} \times 2^V$ be
the candidate generator, mapping a requirement to a proposed type, delta, and
core-service set. Layers 2 and 3 compose into a deterministic \emph{bounded
projection operator} applied to every candidate regardless of $L$'s output
distribution:
\begin{multline}
\Pi(t,\delta,S) = \Big(\textsc{Gw}(\text{inj}),\\
\ \textsc{Clamp}_{[5,50]}\big(\delta_{\text{anchor}} + \textsc{Clamp}_{[-10,10]}(\text{adj})\big),\\
\ S \cap V\Big),
\label{eq:projection}
\end{multline}
with $\textsc{Gw}(v) = v$ if $\text{in-deg}(v)=0$, else the nearest valid gateway;
$\textsc{Clamp}_{[a,b]}(x) = \max(a,\min(b,x))$.

\begin{proposition}[Verifier soundness]
\label{prop:soundness}
Let $\mathcal{G}=(V,E)$ be a dependency graph with at least one node of in-degree $0$. For every candidate $(t,\delta,S)\in T\times\mathbb{R}\times 2^{V'}$ over any entity vocabulary $V'\supseteq V$, the output $\Pi(t,\delta,S)=(v^*,\delta^*,S^*)$ satisfies
\emph{(i)} $\mathrm{in\text{-}deg}(v^*)=0$; \emph{(ii)} $\delta^*\in[5,50]$; \emph{(iii)} $S^*\subseteq V$.
\end{proposition}

\begin{proof}
\emph{(ii)} $\textsc{Clamp}_{[a,b]}$ is total on $\mathbb{R}$ with range exactly $[a,b]$ whenever $a\leq b$; the outer clamp is applied last, so $\delta^*\in[5,50]$ irrespective of the inner clamp's value or of $\delta_{\text{anchor}}$. \emph{(i)} $\textsc{Gw}$ returns its argument only under the guard $\mathrm{in\text{-}deg}(v)=0$, and otherwise a node drawn from the gateway set, which is non-empty by hypothesis. \emph{(iii)} $S\cap V\subseteq V$ for any $S$. Each component is a total function whose codomain is the asserted constraint set, and none reads $L$'s confidence, sampling temperature, or output distribution; the conjunction therefore holds pointwise on all of $\Pi$'s domain.
\end{proof}

\begin{corollary}
\label{cor:zero}
The Physical Boundary Violation Rate and Service Hallucination Rate of the guarded parser are identically zero by construction, for any LLM backend and any prompt.
\end{corollary}

Corollary~\ref{cor:zero} changes how the corresponding entries of
Table~\ref{tab:rq3} should be read: they are not an estimate of a rate that might
have come out otherwise, but a check that the implementation realises the
operator specified here --- a check that Section~\ref{sec:rq3} shows was
warranted. Their evidential value lies in the adversarial evaluations, which
establish that the guarded quantities are ones the unguarded generator actually
violates. Layer 1 admits no analogue: scope membership is a semantic property of
the requirement, not a structural property of $\mathcal{G}$, so no total
projection onto it exists.

\begin{algorithm}[!t]
\caption{Guarded requirement parsing. Lines 2--10 are the non-deterministic generator; lines 11--18 are the deterministic verifier, which reads no confidence signal produced by $L$.}
\label{alg:parser}
\begin{algorithmic}[1]
\REQUIRE requirement text $r$; graph $\mathcal{G}=(V,E)$; calibration table $C$; thresholds $\tau, \tau_{\text{pass}}, \tau_{\text{refuse}}$
\ENSURE intervention $do(X{=}x)$, or \textsc{refused} / \textsc{review}
\STATE $(t_0, \sigma_0) \leftarrow \textsc{RuleMatch}(r, C)$ \COMMENT{archetype, similarity}
\IF{$\sigma_0 \geq \tau$}
    \STATE $(t,\text{adj},S,v) \leftarrow (t_0,\ 0,\ C[t_0].S,\ C[t_0].v)$ \COMMENT{fast path}
\ELSE
    \STATE $(t,\text{adj},S,v,\sigma_L,\kappa) \leftarrow L(r,\mathcal{G},C)$ \COMMENT{one LLM call}
    \IF{$\sigma_0 < \tau$ \textbf{and} $\sigma_L < \tau$}
        \STATE $\text{adj} \leftarrow 0$ \COMMENT{fall back to unmodified anchor}
    \ENDIF
\ENDIF
\STATE $s \leftarrow \textsc{LogisticScore}(\sigma_0, \sigma_L, \textsc{Overlap}(r, C[t]), \kappa)$
\IF{$s \geq \tau_{\text{refuse}}$} \RETURN \textsc{refused}
\ELSIF{$s \geq \tau_{\text{pass}}$} \RETURN \textsc{review}
\ENDIF
\STATE $v^{*} \leftarrow v$ \textbf{if} $\operatorname{in-deg}(v){=}0$ \textbf{else} $\textsc{NearestGateway}(\mathcal{G})$
\STATE $S^{*} \leftarrow S \cap V$
\STATE $\delta^{*} \leftarrow \textsc{Clamp}_{[5,50]}\!\big(C[t].\delta + \textsc{Clamp}_{[-10,10]}(\text{adj})\big)$
\RETURN $do(\text{Workload}(v^{*}){=}\delta^{*})$ with scope $S^{*}$
\end{algorithmic}
\end{algorithm}

Algorithm~\ref{alg:parser} makes the separation concrete: every path through the
verifier terminates in either an abstention or an intervention satisfying
Proposition~\ref{prop:soundness}, and no branch condition there depends on a
value $L$ reports about its own reliability. The dependency topology is separately
verified acyclic at construction time.

\label{sec:workload-propagation}

The node set partitions as $V = V_W \cup V_R$ into cross-service workload nodes
and per-service resource nodes, with edges restricted by default to two kinds:

\begin{equation}
\begin{aligned}
\text{(Tier 1, workload):}\quad W_j &= f_j(PA_{W_j}) + N_{W_j}, \quad PA_{W_j} \subseteq V_W, \\
\text{(Tier 2, resource):}\quad R_j &= g_j(W_j) + N_{R_j}.
\end{aligned}
\label{eq:tiers}
\end{equation}

Each resource node therefore takes its own service's workload as its only parent:
no $R \to R$ or $R \to W$ edges. Section~\ref{sec:rq5-do} shows this restriction
is the model's most valuable property, though not for the reason we originally
adopted it.

Mechanisms are fit as $g_j(w) = \boldsymbol{\beta}^\top w + \beta_0$ with
coefficients constrained to
$\boldsymbol{\beta}^* = \operatorname*{argmin}_{\boldsymbol{\beta}\geq\mathbf{0}}
\lVert \mathbf{y} - X\boldsymbol{\beta}\rVert_2^2$, which guarantees
$\partial g_j/\partial w \geq 0$ and enforces a monotonically non-decreasing
response to load by construction --- applied uniformly to both tiers. Latency
instead uses a queueing-inspired transform
\begin{equation}
\phi(w) := \frac{w}{c-w}, \qquad c \approx 1.5 \max(W_{\text{train}}),
\label{eq:queueing}
\end{equation}
fit as $R^{\text{Lat}}_j = \beta\,\phi(W_j) + \beta_0$ with $\beta\geq 0$;
as $w \to c^-$ this approximates the heavy-traffic behaviour $\rho/(1-\rho)$ of an
M/M/1 queue \cite{kingman1961}, by analogy rather than derivation.

\textbf{Post-simulation uncertainty.} Verification bounds the \emph{input} delta,
but a downstream node reached through propagation can still land outside its own
training envelope. Each simulation therefore classifies every downstream node's
projected mean against that node's training percentiles, and the report node
appends an extrapolation caveat naming the flagged nodes when the worst
confidence is low. We present this as an annotation rather than a verification
layer because its specificity is poor: against 150 real cases it fires on $80\%$,
and $147/150$ activations trace to one node whose heavily right-skewed training
distribution (P95 $=0.21$, max $=49.0$) makes its band narrower than a typical
delta. We name the failure mode --- single-node dominance under percentile
calibration --- and leave recalibration to Section~\ref{sec:future-work}, since
it requires an outlier-resistant estimator rather than a threshold adjustment.

The conflict is inherent. An RCA benchmark holds its normal period at steady
state \emph{by design}, so that injected faults stand out against a stable
baseline. That same stability erases the load signal capacity forecasting needs.
The property that makes a dataset good for diagnosis makes it unusable for
forecasting, which is why no benchmark serves both --- and, we argue in
Section~\ref{sec:discussion}, a second reason (independent of the absence of
ground truth) that the microservice literature has remained retrospective.

\textbf{Sock Shop and Train Ticket} (RCAEval \cite{pham2024rcaeval}) supply real
dependency topologies with human-readable service names: 7 and 28 services
respectively, 90 fault-injection scenarios each, with an explicit injection
timestamp. We use them for everything that needs semantics --- requirement
parsing, entity grounding, blast radius --- and for the interventional test of
Section~\ref{sec:results}, where fault injection serves as genuine ground truth
for an intervention, which is the purpose the data was collected for.

\textbf{Alibaba cluster trace v2021} \cite{alibaba2021} supplies what the RCA
benchmarks cannot: production traffic across 1{,}303 microservices and 90{,}000
containers, with per-service call rates (\texttt{*\_MCR}), CPU and memory
utilisation, response times, and a sampled call graph. We use the first five
hours of the trace. Service names are hashed, so no requirement can be grounded
in them; we therefore use this dataset only for the capacity model, never for
the parser.

We report per-system rather than pooled throughout,
to avoid obscuring topology-specific variation.



\subsection{Baselines for Comparison}
\begin{itemize}
    \item \textbf{(B0) Rule-Only Parser:} a deterministic keyword-matching classifier with no LLM and no learned adjustment, used as the accuracy floor for requirement parsing.
    \item \textbf{(B1) Unguarded Zero-Shot LLM:} the same live LLM backend as our proposed parser, prompted directly with no calibration table and no runtime guards.
    \item \textbf{(B2) Unguarded Few-Shot LLM:} as B1, but with the system topology and calibration table given as in-context examples, still without any runtime guard.
    \item \textbf{(B3) Non-Causal Regression Baselines:} Linear Regression, Gradient Boosting Regression, and a Gaussian Process Regressor, evaluated under the out-of-distribution protocol of Section~\ref{sec:results}, used to test whether causal structure yields an accuracy advantage over standard regressors. \emph{Matched training samples.} Every model in the comparison --- baselines and both SCM variants --- is fit on one identical subsample of the training split ($n{=}2000$, fixed seed), rather than on whatever sample size each method scales to. The cap is set by the Gaussian Process, whose $O(n^3)$ fit does not admit the full split. This matters because an earlier version of the harness fit the baselines on the full training set ($\sim$43k points) while subsampling the Gaussian Process and the SCM, an $86{\times}$ disparity that confounds model class with training-set size; under matched samples, a difference between two models is attributable to the models.
    \item \textbf{(SCM variants)} The comparison reports two instantiations of the same causal graph, differing only in the mechanism class fit at each node. \textsc{SCM-Deployed} uses the non-negative linear mechanism that the framework actually ships (Section~\ref{sec:backpressure-edge}) and that RQ1 evaluates. \textsc{SCM-Auto} lets DoWhy select the mechanism by cross-validation, and answers the separate question of whether causal structure helps when the mechanism class is unconstrained. Reporting only the latter, as an earlier version did, produces the anomaly that the RQ1 and RQ2 tables describe different models of the same system; reporting only the former conflates the framework's engineering choice with the scientific question. We report both.
    \item \textbf{(B4) Uniform Delta Injection:} a naive propagation baseline that assumes every downstream service's workload changes by exactly the same percentage as the injected upstream delta, bypassing the dependency-graph propagation entirely.
\end{itemize}

\subsection{Evaluation Metrics}
\textbf{Forecasting accuracy.} We report MAPE, RMSE, and $R^2$ at full test-set resolution --- on every held-out point, rather than on quantile-bucket averages, which understate error substantially (Section~\ref{sec:results}). MAPE is sensitive to small denominators \cite{hyndman2006accuracy}, and several nodes in these testbeds are heavy-tailed with near-zero baselines; we therefore report median alongside mean percentage error, conduct all model comparisons on ranks, and quantify effect sizes with rank-based statistics invariant to monotone rescaling of the error metric (Section~\ref{sec:background}). Points with a measured target of exactly zero are excluded from MAPE, as the ratio is undefined there; the excluded mask depends only on the ground truth and is therefore identical across all compared models. For capacity decisions specifically we also report threshold-crossing F1, which scores the decision the framework actually emits rather than the magnitude behind it.

\textbf{Parser reliability.} Let $\mathcal{R}$ be the evaluated requirement set and, for $r\in\mathcal{R}$, let $(v_r,\delta_r,S_r)$ be the parser's emitted intervention. We define
\begin{align*}
\text{PBVR} &= \tfrac{1}{|\mathcal{R}|}\left|\{r : \delta_r \notin [5,50]\}\right|,\\
\text{SHR} &= \tfrac{1}{|\mathcal{R}|}\left|\{r : S_r \not\subseteq V\}\right|,\\
\text{GMR} &= \tfrac{1}{|\mathcal{R}|}\left|\{r : v_r \neq g^{*}\}\right|,
\end{align*}
i.e.\ the fractions of requirements whose emitted delta leaves the physical envelope, whose service set contains a node absent from $\mathcal{G}$, and whose injection point differs from the reference gateway $g^{*}$. On a single-gateway topology, $v_r \neq g^{*}$ and $\operatorname{in-deg}(v_r)\neq 0$ coincide; on a multi-gateway topology they would not, and GMR as defined here is the stricter of the two. Anchor MAE is the mean absolute deviation of $\delta_r$ from the calibration table's empirically anchored value for the matched archetype, expressed in \emph{percentage points} of workload delta (we retain the \% sign for readability, but the quantity is a difference of two percentages, not a ratio). Rates are reported as mean $\pm$ standard deviation across independent live-LLM repeats, with Wilson $95\%$ confidence intervals over the pooled calls. We further report mean end-to-end latency, LLM calls per requirement, and the fraction of requirements resolved without an LLM call (fast-path bypass rate).

\textbf{Attribution of guard effect.} PBVR, SHR, and GMR are properties of the \emph{emitted} intervention, and Corollary~\ref{cor:zero} makes the first two identically zero for any guarded configuration. A guarded-versus-unguarded contrast on these metrics therefore cannot by itself establish that a guard is load-bearing, since a generator that never violates the constraint would produce the same table. We separate the two by measuring, for each layer, the rate at which it \emph{fires} --- alters a candidate --- on both the benign benchmark and a purpose-built adversarial set (Sections~\ref{sec:entity-grounding}, \ref{sec:bounded-projection}). Firing rate, not outcome rate, is the quantity that distinguishes an active guarantee from a vacuous one.

\section{Results and Evaluation}
\label{sec:results}

We organize results around five research questions. RQ1--RQ2 evaluate forecasting accuracy and compare the SCM against non-causal regressors. RQ3 evaluates Parser reliability under the three-layer verification architecture. RQ4 tests graph-based propagation against a uniform-delta baseline, and RQ5 measures multi-agent coordination overhead.

\subsection{RQ1: Can LLM-Proposed Interventions Be Constrained by Guarantees That Are Both Provable and Load-Bearing?}
\label{sec:rq1}
We evaluate 50 hand-authored requirement prompts (In-Distribution, Complex Multi-Hop, Subtle Read-Only, and Adversarial subsets) against four parser configurations, using a live LLM backend rather than a scripted stand-in, so that failure modes reflect genuine model behavior rather than an experimenter-authored fixture. The primary arm uses \texttt{gemini-flash-lite-latest} over $3$ repeats; Section~\ref{sec:rq1-backend} replicates the benchmark on a second backend from a different vendor to test whether the failure rates are specific to a lite-tier model.

Across 3 independent live-LLM repeats (temperature 0.2), the unconstrained LLM (B1) misdirects the injection point away from the gateway on \emph{every} prompt (GMR $=100.0\pm0.0\%$), hallucinates services on $91.3\pm1.2\%$ of prompts (SHR), and violates a physical bound on $38.0\pm2.0\%$ (PBVR); these compound into a mean Anchor MAE of $844.6\pm568.2\%$ (range $188.5$--$1173.4\%$). This mean is right-skewed, as in RQ1: the per-repeat median is far lower ($22.8$--$30.0\%$), inflated by only 2--3 of 50 prompts per repeat going wildly out of bound -- most strikingly a ``DDoS via millions of fake promo-code requests'' prompt answered with a literal $50{,}000\%$ delta. The instability matters independently of the mean: an unguarded LLM's output is not merely inaccurate on average but unstable run to run, a property no single-repetition evaluation can reveal. In-context calibration (B2: few-shot topology and calibration table, still no runtime guard) closes most of the gap on two metrics (SHR $\to2.0\pm0.0\%$, Anchor MAE $\to38.6\pm0.2\%$) but leaves GMR at $84.7\pm1.2\%$ and PBVR at $14.7\pm1.2\%$: better prompting alone still misdirects the injection point on roughly four out of five prompts, every time.

The guarded configuration attains $0.0\pm0.0\%$ on all three structural failure modes, with an Anchor MAE ($1.6\pm0.1\%$) below the deterministic Rule-Only floor (B0, $2.8\pm0.0\%$) despite invoking the LLM on every prompt and resolving only $80.7\%$ of them with a numeric verdict (Section~\ref{sec:edge-of-scope}). Two of these three zeros follow from Corollary~\ref{cor:zero} and are confirmatory; what the comparison establishes is the premise the corollary needs to be meaningful, namely that the guarded quantities are ones an unguarded generator violates at high rate even when given identical context.

That premise is carried by the B2 contrast, and it is important to state precisely what it does and does not isolate. B2 sees the same topology and calibration table as the verified configuration, so the residual improvement on PBVR ($14.7\%\to0.0\%$) separates \emph{enforcing} a bound from \emph{displaying} it. The two configurations differ in prompt as well as in runtime enforcement, however, so the GMR difference ($84.7\%\to0.0\%$) is not attributable to Layer 2 alone. Within the guarded pipeline the LLM proposed \texttt{front-end} unanimously across all 150 calls, meaning the observed GMR of zero records the generator avoiding an error rather than the verifier correcting one. The evidence that Layer 2 corrects is separate and direct: on an 18-prompt adversarial set constructed to elicit non-gateway proposals, the LLM proposed an invalid injection point on every prompt and the fallback corrected all $18$ (Section~\ref{sec:entity-grounding}). We therefore claim for Layer 2 that it is sound (Proposition~\ref{prop:soundness}) and demonstrably active under adversarial input, not that it accounts for the B2-to-guarded gap on this benchmark. Gateway \emph{disambiguation} among several valid candidates remains untested, as this topology has one.

\subsubsection{Does model capability substitute for the verifier?}
\label{sec:rq1-backend}
The rates above are those of a lite-tier model, which invites the objection that
a stronger generator would render the verifier redundant --- an objection that,
if correct, would leave Proposition~\ref{prop:soundness} sound but vacuous in
practice. We therefore repeated the benchmark on \texttt{gpt-oss-120b}, an
open-weight $117$B-parameter model from a different provider, served via Groq.
Two properties motivate this choice over a larger proprietary model. First, it
is a different vendor and training pipeline, so agreement is not an artifact of
one model family. Second, its weights are public: closed snapshots are withdrawn
from APIs and become unreproducible, which we observed directly during this work
when the entire Gemini~2.x family returned \texttt{404 no longer available} and
\texttt{gemini-2.5-pro} reported \texttt{no longer available to new users}.
A benchmark anchored to public weights does not decay in this way.

The replication separates two things that the single-backend result conflates.
Capability buys \emph{semantic} plausibility: the larger model's Anchor MAE falls

GMR is $90\%$ (In-Distribution), $100\%$ (Complex Multi-Hop), $100\%$ (Subtle
Read-Only), and $80\%$ (Adversarial Stress) --- so it reflects a systematic
failure to respect a topological constraint rather than sensitivity to prompt
difficulty. This is the distinction the verifier is built on: the guards enforce
membership and in-degree invariants, which are exactly the properties a more
capable generator did not recover on its own. The guarded configuration attains

open-weight run is a single repeat, fixed in advance because the free-tier
serving quota is a daily token cap, and it therefore carries no run-to-run

resolve it; with one repeat we cannot distinguish a real backend interaction
from sampling noise, and in-context calibration is not part of our contribution.
(iii) Two backends are a replication, not a sample of the model population; the
claim is that the violation rates are not an artifact of one lite model, not
that they are invariant across all generators.

\subsection{RQ2: What Does Abstention Cost, and What Guarantee Is Attainable at This Sample Size?}
\label{sec:rq2}

Layers~2 and~3 admit a sound total projection because the properties they enforce
are structural. Scope membership is not: whether a requirement resembles any
calibrated archetype is a semantic judgement, and no projection onto it exists.
The Scope Gate therefore abstains rather than repairs, under a statistical rather
than a structural guarantee --- and the honest statement of that guarantee is
bounded by the calibration set, not by the confidence level we choose.

Section~\ref{sec:edge-of-scope} gives the derivation; we report the operating
point and its cost here. On the pooled $81$-prompt calibration set
($21$ out-of-scope, $60$ legitimate): no out-of-scope prompt reaches the
auto-pass zone ($0/21$, Wilson $95\%$ CI $[0.0,15.5]\%$), $16/81$ ($19.8\%$) are
routed to human review, and the auto-refuse zone's false-positive rate is
$3/60$ ($5.0\%$), down from $10/60$ ($16.7\%$) for the single-threshold design.
Across RQ1's $150$ live calls, $12.0\%$ returned \texttt{NEEDS\_HUMAN\_REVIEW}
and $7.3\%$ were refused, leaving $80.7\%$ with a numeric verdict. Roughly one
request in five therefore receives something other than a number --- a coverage
cost the reliability metrics of Table~\ref{tab:rq3} cannot express, and one we
report rather than absorb.

\textbf{The attainable guarantee is set by $n$, not by $\alpha$.} Split conformal
places the threshold at the $\lceil (n{+}1)\alpha \rceil$-th order statistic, so
any $\alpha < 1/(n{+}1)$ selects the extreme order statistic and certifies
nothing beyond it. With $21$ out-of-scope calibration points the tightest
certifiable miss-rate is $1/22 = 4.5\%$. The nominal $\alpha = 0.01$ we used in
an earlier calibration is therefore unattainable here, and the degeneracy is
directly visible in the output: at $n_{\text{pos}}=11$, $\alpha = 0.05$ and
$\alpha = 0.01$ return the \emph{identical} threshold ($0.5343$), because both
round to the same order statistic. We report the achievable bound instead. The
$\beta = 0.05$ bound on the legitimate side is attainable ($1/61 = 1.6\%$).

\textbf{We also report where the gate fails.} Its predecessor tested scope by
keyword overlap alone. An $11$-prompt adversarial set --- ten out-of-taxonomy
requirements each carrying a single polysemous keyword (``order'' as in sorting,
``code'' as in source code), plus a keyword-free control --- evaded refusal on
all ten, on every repeat ($30/30$); a request to refactor Java source code was
classified as \texttt{APPLY\_PROMO\_CODE}. Only the control was refused. That
failure is what motivated the four-signal conformal score, which has not itself
been attacked by a comparably sized set.

\subsection{RQ3: Does the Framework Transfer to a Second System, and What Does Transferring Reveal?}
\label{sec:rq3}

A guarantee proved on paper and validated on one system is not thereby validated
as implemented. We deployed the parser to Train Ticket --- $68$ nodes against
Sock Shop's $7$, a different domain, and a topology with $14$ gateways rather
than one --- and report both the deployment and what it exposed.

\textbf{The taxonomy is graph-derived, as the specification claims.} Each
archetype's affected-service set is computed by bounded breadth-first traversal
from seed services in the real dependency graph, not enumerated by hand; only
descriptions, keywords, and the expected-delta anchor are authored manually, which
is the division Table~\ref{tab:general-spec} predicts. The resulting ten
archetypes span $2$ to $12$ services with a mean pairwise Jaccard similarity of
$0.21$ and no identical pairs, so they are distinguishable --- the failure mode
the specification warns about.

\textbf{Transferring exposed three defects that single-system validation could
not.} Each was invisible on Sock Shop for a structural reason, not by chance.

\begin{enumerate}
    \item \emph{Blast radius.} Expanding from the gateway rather than from
    archetype seeds reached $28$ of $68$ nodes for every archetype, rendering
    them mutually indistinguishable. Sock Shop's gateway has out-degree $3$; Train
    Ticket's has $15$, so the same traversal saturates the graph.
    \item \emph{Gateway selection.} The fallback chose the alphabetically first
    in-degree-zero node, which on Train Ticket is an \emph{administrative}
    service. Every customer-facing requirement was routed to it. With one
    gateway, every fallback path returns the same node and the defect cannot
    surface. We now prefer, in order, a gateway named by the LLM, one appearing
    in the matched archetype's own call chain, and a system-declared default.
    \item \emph{An invariant violation in the verifier itself.} When the service
    filter removed every proposed service, it returned the hard-coded literal
    \texttt{['front-end']}. On any system without a node of that name the guard
    \emph{inserts} a non-existent service --- violating
    Proposition~\ref{prop:soundness}(iii), the very invariant it exists to
    enforce, and falsifying Corollary~\ref{cor:zero} off Sock Shop. The fallback
    is now the running system's own gateway, which belongs to $V$ by definition,
    or the empty set, which also satisfies the invariant.
\end{enumerate}

The third defect is the substantive finding. Proposition~\ref{prop:soundness}
is correct; the implementation violated it, and no amount of testing on Sock Shop
--- where \texttt{front-end} happens to be a valid node --- could have revealed
that. A verified design requires its implementation to be validated on a system
whose accidental properties differ, and porting is the cheapest way to obtain
one.


\subsection{RQ4: Does the Capacity Model Forecast --- and How Would We Know If It Did Not?}
\label{sec:rq4}

An accuracy number is only meaningful if the evaluation that produced it could
have failed. Our first attempt at this question could not: measured on an RCA
benchmark with MAPE alone, the memory mechanism scored $2$--$4\%$ error and
looked like a success, while explaining essentially none of the variance it was
credited with. We therefore report the protocol before the numbers.

\subsubsection{A protocol with failure modes}
\label{sec:rq4-protocol}
Four safeguards, each able to return a negative result:

\begin{enumerate}
    \item \textbf{Signal gate.} Before any accuracy claim, we report $R^2$ of the
    predictor against the target on the \emph{undivided} data. If workload
    explains no variance, no accuracy claim about a workload-driven model is
    meaningful, however small its error.
    \item \textbf{A baseline that ignores the predictor.} Every model is scored
    against a constant that predicts the training mean. A model that cannot beat
    it has learned nothing, whatever its MAPE.
    \item \textbf{Negative control.} The entire pipeline is re-run with the
    workload column permuted within each service, destroying the relationship
    while preserving the marginal distribution. Skill must collapse to zero. If
    it does not, the metric is measuring something other than the workload
    relationship.
    \item \textbf{Skill, not raw error.} We report
    $\mathrm{skill} = 1 - \mathrm{MSE}_{\text{model}}/\mathrm{MSE}_{\text{constant}}$.
    Absence of signal appears automatically as $\mathrm{skill}\leq 0$, which raw
    MAPE cannot express.
\end{enumerate}

In-distribution (random $70/30$) and out-of-distribution (train on the lowest
$67\%$ of workload, test on the highest $33\%$) are reported separately: a model
that has not learned a relationship \emph{within} the observed range cannot
meaningfully be asked to extrapolate beyond it.

memory forecasting accuracy, and note that MAPE reported without a
predictor-free baseline cannot distinguish the two cases.


\subsection{RQ5: What Does Causal Structure Buy --- the Graph, the $do$-Operator, or Neither?}
\label{sec:rq5}

The framework carries two distinct causal commitments: a dependency \emph{graph}
along which load propagates, and an \emph{interventional operator} defined over
that graph. They are usually defended together. We evaluate them separately, and
they do not survive together.

\subsubsection{(a) The graph: a measurable advantage}
\label{sec:rq5-graph}

We compare fitted Tier-1 propagation against the assumption that a downstream
service's load changes by the same percentage as its upstream parent's --- the
implicit model behind most back-of-envelope capacity estimates. Topology is taken
from the Alibaba call graph (\texttt{um}$\to$\texttt{dm}, restricted to
service-to-service RPC and HTTP calls, excluding database, queue, and cache
edges); $106$ edges carry at least $5{,}000$ calls, of which $27$ have workload
data at both endpoints.

where six non-root services and a bootstrap interval containing zero could not
separate the two at all.

\subsubsection{(b) The $do$-operator: no estimation advantage, and the reason is structural}
\label{sec:rq5-do}

In the configuration this framework uses --- an intervention applied at a
gateway, which by construction has in-degree zero, over a DAG with no modelled
latent confounders --- the truncated factorisation removes no edges, because the
intervened node has none entering it. The interventional and observational
distributions therefore coincide identically:
$P(Y \mid do(X)) = P(Y \mid X)$. This is a direct consequence of the backdoor
criterion rather than a finding, but its empirical consequences are measurable,
and we report four independent tests because the equality is easy to state and
easy to overlook in practice.

\textbf{The deployed mechanism is numerically the same model as the regression
baseline.} Non-negative least squares coincides with ordinary least squares
whenever the unconstrained slope is already non-negative, so the constraint binds
only where the fit would otherwise predict a resource \emph{decrease} under
rising load. Across two topologies it binds on $19$ of $105$ service--metric
pairs: predictions are identical on $12/21$ Sock Shop and $74/84$ Train Ticket
pairs, including $7/7$ and $27/28$ of the CPU pairs. On those pairs the
comparison is not between model classes, and the paired test is undefined. The
deployed mechanism takes a sole win on $0$ of $21$ and $0$ of $84$ pairs.

\textbf{No confounder is present to adjust for.} We tested the two candidates
that a microservice deployment makes plausible. Physical co-location: for pairs
with no call-graph edge, the partial correlation of two services' CPU after
removing both services' own workload is no higher when they share a Kubernetes
node than when they do not ($n=2{,}340$, Mann--Whitney $p=0.546$,
common-language effect $0.498$). Global traffic: conditioning additionally on
total cluster workload reduces the residual correlation by $1.2\%$.

\textbf{Backdoor adjustment does not improve interventional transfer.} Using
RCAEval's fault injection as real interventional ground truth, we fitted
estimators on pre-injection data and evaluated them on the post-injection period.
Adjusting for the intervened node's parent, as the backdoor formula prescribes,
beat the naive conditional estimator on $553$ of $1{,}080$ pairs --- a coin flip
--- with a median difference of $0.000$. Both were roughly five times worse than
simply using the service's own workload (median MAPE $36.6$ and $38.0$ against
$6.9$).

\textbf{Counterfactual reasoning reduces to carrying the residual.} Abducting the
noise term and propagating it structurally through the graph beat simply adding
the observed residual on $47.5\%$ of cases. Abduction itself is worthwhile
--- carrying the residual beats the marginal prediction on $80\%$ of cases, a
$15.7\%$ reduction in median error --- but the benefit decays within roughly
five sampling intervals and turns harmful beyond fifteen, and the structural
propagation adds nothing to it.

\textbf{What transfers under intervention is extrapolation robustness, not
confounding adjustment.} Predictors using a \emph{resource} as a parent degrade
sharply under real intervention (median $+4.9$ MAPE points) while those using the
service's own \emph{workload} do not ($+0.3$). Separating post-injection points
by whether the parent remained inside its training range identifies the cause:
inside the range the two are equivalent ($63.2$ against $55.9$ on the worst
edge), and only outside it do they diverge ($1264.6$ against $73.2$). The
two-tier restriction --- resources depend only on their own service's workload
--- is therefore valuable, but as a prior that keeps parents inside their
observed range, not as a causal identification device. The backpressure extension
of Section~\ref{sec:backpressure-edge} relaxes exactly this restriction, and pays
for it: on the \texttt{orders}$\to$\texttt{shipping} CPU edge it degrades by
$365$ MAPE points under intervention where the two-tier mechanism degrades by
$16$.

\subsubsection{Answer}
The graph earns its place: propagation along real dependencies beats the uniform
assumption on $85\%$ of edges in-distribution and is more consistently positive
out of distribution. The $do$-operator, in this configuration, does not: it
coincides with conditioning, there is no confounding for it to adjust, and
neither backdoor adjustment nor counterfactual abduction improves on simpler
alternatives. We identify the conditions under which it would --- internal-node
interventions with confounded parents, and simultaneous ancestor--descendant
interventions --- and report that this deployment satisfies neither.


\subsubsection{Operational consequence: does the pipeline change the verdict?}
\label{sec:rq1-operational}
\label{sec:operational}
Against a single-LLM-call baseline given the same topology and calibration table
but required to guess the capacity status itself, the guarded pipeline disagrees
on the SAFE/WARNING/CRITICAL verdict for $52.9\%$ of $136$ runs ($47$
requirements $\times$ 3 repeats, refusals excluded), rising to $69.6\%$ on the
adversarial subset. Structural correctness replicates RQ1's pattern: the single
call still violates the physical delta bound on $27.3\%$ of prompts against
$0\%$ for the pipeline, at a cost of $1.91$ LLM calls and $3.9{\times}$ latency.

This is the closest the paper comes to evidence that the modelling machinery
changes the engineering answer rather than merely its provenance. We state its
limit plainly: it measures \emph{divergence} from a simulated reference, not
\emph{accuracy}, because no ground truth exists for an unbuilt requirement's
impact. The $136$ observations are repeated runs over $47$ requirements, so the
rate is a point estimate without an attached interval.


\section{Discussion and Threats to Validity}
\label{sec:discussion}

\subsection{Why the RCAEval Measurements Were Uninformative}
\label{sec:cpu-ceiling}
An earlier version of this work read the per-service spread in Sock Shop CPU
error as three distinct failure mechanisms, and memory's $2$--$4\%$ MAPE as
evidence that the difficulty was specific to CPU. The signal gate of
Section~\ref{sec:rq4-gate} supersedes both readings: workload explains
$R^2 = 0.0034$ of the variance in CPU, memory, and socket count alike, so there
was no relationship for any mechanism to capture, and memory's low error reflects
its near-invariance rather than an easier target.

We retain the episode because three properties made the mistake durable, and none
is specific to us: the error metric was small and therefore looked like success;
the negative $R^2$ values that contradicted it were present in our own results but
rationalised as an artefact of the train-low/test-high split; and no baseline
ignoring the predictor was ever computed, so nothing in the evaluation could
return a negative answer. A covariate-selection lesson survives the correction:
adding each service's memory and socket count as regressors lowered
cross-validated in-distribution error substantially while failing under the
held-out protocol, because a covariate that must itself be extrapolated at
prediction time contributes variance rather than information.


\subsection{The Backpressure Extension: A Cautionary Case}
\label{sec:backpressure-edge}

The two-tier default gives each resource node only its own service's workload as
a parent. We relaxed it on a small node set, adding a directly-calling service's
CPU as a second parent to capture synchronous backpressure, and validated the
addition on held-out data under the out-of-distribution protocol: mean
full-resolution MAPE fell on $3$ of $21$ Sock Shop CPU/memory nodes and on all
$20$ of $84$ eligible Train Ticket CPU nodes, with sign-inversions falling from
$30$ to $24$. On the evidence available at the time, a $23/23$-node improvement
justified deploying it.

The interventional test of Section~\ref{sec:rq5-do} shows what that evidence
could not. Under real intervention, a mechanism whose parent is a \emph{resource}
degrades sharply once that parent leaves its training range, because resource
metrics under intervention routinely do. On the
\texttt{orders}$\to$\texttt{shipping} CPU edge the extended mechanism degrades by
$365$ MAPE points where the two-tier mechanism degrades by $16$; inside the
training range the two are indistinguishable ($63.2$ against $55.9$), and only
outside it do they separate ($1264.6$ against $73.2$).

We report this as a correction to our own design decision rather than a general
argument against $R\to R$ edges. The methodological point is narrower and, we
think, more useful: held-out accuracy under an observational protocol does not
predict behaviour under intervention, even when the held-out protocol is itself
out-of-distribution in load. The property that distinguishes the two-tier
restriction is that workload parents leave their observed range far less often
than resource parents do --- a robustness prior, not a causal identification
device.


\subsection{Deriving the Scope Gate}
\label{sec:edge-of-scope}
Both parsing paths fail silently in the same direction. The rule-based classifier
falls back to a default archetype with no ``no reliable archetype'' signal, and
the LLM branch is instructed to always select the closest-matching known
archetype rather than decline --- a deliberate anti-hallucination choice whose
side effect is that it never reports insufficient calibration data. Either path
alone returns a confident numeric verdict for a requirement sharing nothing with
the system's taxonomy.

Our first gate tested scope by keyword overlap against the selected archetype's
own keyword list, with zero overlap triggering refusal. It is defeated by a
single incidental word (Section~\ref{sec:rq2}), which motivated a scored gate.
Multilingual sentence-embedding similarity was tried and rejected: across two
models \cite{wang2024multilinguale5} and two description styles the best
operating point reached $F_1 = 0.31$, because legitimate and adversarial prompts'
similarity distributions overlap (means $0.82$ against $0.83$). A structured
self-declaration performed far better: asking the LLM, within the same extraction
call, whether the requirement describes a genuine customer-facing action closed
the adversarial evasion rate to $0/11$ over 61 live calls, while flagging 12 of
50 legitimate prompts --- seven of which no reasonable gate should pass (a hidden
gRPC gateway bypass, deleting all users) and five genuine over-refusals on
passive content where ``customer-facing'' is a defensible judgement either way.

Rather than combine keyword overlap, the LLM's pick-similarity, the rule-based
similarity, and the self-declaration by inspection, we fit a logistic score over
the four and calibrate its thresholds by split-conformal prediction
\cite{angelopoulos2023conformal}, in the style recent text-to-SQL work uses for
schema-linking abstention \cite{chen2025rts}. A single threshold calibrated on 61
prompts reached $100\%$ recall at an $18.0\%$ false-refusal rate, but a held-out
check on 20 freshly authored prompts showed it matched a naive combination
exactly, both missing the same borderline case. Pooling to $n{=}81$ permitted a
\emph{second} threshold: below
$\tau_{\text{pass}}$ a prompt auto-passes, at or above $\tau_{\text{refuse}}$ it
auto-refuses, and the band between returns \texttt{NEEDS\_HUMAN\_REVIEW} rather
than guessing. Section~\ref{sec:rq2} reports the resulting operating point, its
coverage cost, and the sample-size bound on the guarantee.

Two conditions qualify the design. The logistic score is fit on the original 61
prompts while the thresholds use the pooled 81, so those 61 contribute
cross-validated scores and the 20 held-out prompts genuinely out-of-sample ones;
exchangeability across the pooled set is therefore only approximate, and the
conformal statement should be read as a design target supported by the observed
rates rather than a certified bound. Both thresholds are also evaluated on the
same 81 points used to set them.


\subsection{Threats to Validity}
\label{sec:threats}
We organise threats following Wohlin et al.\ \cite{wohlin2012experimentation}.

\textbf{Construct.} PBVR and SHR are zero by construction
(Corollary~\ref{cor:zero}), so an outcome contrast against unguarded baselines
cannot by itself show a guard is load-bearing; we therefore report layer
\emph{firing} rates on adversarial sets, whose small, author-constructed size is
the residual risk. The gateway-misdirection contrast between B2 and the guarded
configuration is confounded by a prompt difference and is not claimed as a guard
effect. The operational divergence of Section~\ref{sec:operational} measures
disagreement with a simulated reference, not accuracy against ground truth, which
does not exist for an unbuilt requirement.

\textbf{Internal.} The guarded row of Table~\ref{tab:rq3} was re-measured after
B0--B2 were collected, following a defect fix and the Scope Gate replacement;
B0--B2 were not re-run, as their code paths do not invoke the parser. The Scope
Gate's score is fit on 61 prompts while its thresholds use the pooled 81, and
both are evaluated on those same 81 points, so the reported operating point is
optimistic relative to a fully held-out estimate.

\textbf{Conclusion.} Where the deployed mechanism and linear regression produce
identical predictions ($12/21$ and $74/84$ pairs) the paired test is undefined
and any effect size rests on the discordant handful; we report identical-pair
counts alongside every such comparison. RQ4 and RQ5a rest on a negative control
rather than significance alone, and both pass. The Tier-1 comparison uses 27
edges, limited by the overlap between services in the call graph and in the
metric table rather than by trace duration. The conformal bound is limited by
$1/(n_{\text{cal}}{+}1) = 4.5\%$ rather than by the nominal $\alpha$.

\textbf{External.} Accuracy conclusions differ between datasets, so a third
cannot be assumed without re-running the protocol. Parser validation uses two
systems but one taxonomy author. RQ1 replicates on two backends from different
vendors (Section~\ref{sec:rq1-backend}), which establishes that the unguarded
failure rates are not an artifact of one lite model, but two models are not a
sample of the generator population: a frontier proprietary model remains
untested, and the open-weight arm is a single repeat. The operational comparison
of Section~\ref{sec:rq1-operational} uses one backend only. The Alibaba
analysis uses five of twelve available hours, and its hashed service names
preclude any parser evaluation there.

\textbf{Scope.} The pipeline handles one intervention per requirement, applied at
a gateway. Section~\ref{sec:rq5-do} argues this is appropriate for
customer-facing requirements, whose load enters at the system boundary, and
identifies the excluded cases --- background jobs, asynchronous consumers, and
features that alter internal behaviour without changing external load --- as
requiring internal-node interventions we do not support.

The gateway set, known-service set, and archetype candidate services are
graph-derivable and are computed that way in the current implementation;
Section~\ref{sec:rq3} exercises this on Train Ticket. Archetype descriptions and
keywords should be drawn from the target system's documentation or API
specification, a route we recommend but did not use for the present hand-authored
tables. The last two rows cannot be shortcut: expected workload magnitude is an
empirical property of real traffic, and the numeric bounds are only as
trustworthy as the knee-point and adversarial analysis behind them, demonstrated
once here rather than assumed to transfer unchanged.


\subsection{Future Work}
\label{sec:future-work}
Three directions follow directly. The uncertainty annotation requires an
outlier-resistant quantile estimator rather than per-node threshold adjustment,
since its failure originates in quantile estimation on heavy-tailed samples.
Validating prospective attribution --- whether the framework ranks affected
services correctly --- requires an intervention on \emph{load}, which no public
dataset provides and which a controlled load sweep would supply; the same
infrastructure would permit the strongest available evaluation, implementing a
forecast requirement and measuring the deployed system against the prediction
made beforehand. Finally, the confounding we measure at production scale
(Section~\ref{sec:rq5-do}) makes internal-node interventions with node-load
adjustment a motivated extension, at the cost of redefining the gateway invariant
in Proposition~\ref{prop:soundness}.


\section{Conclusion}
\label{sec:conclusion}
We asked what can be guaranteed about an LLM's output when that output is
consumed not by a person but by an analysis pipeline, and we asked it in a
setting where validity is decidable: translating an unbuilt requirement into a
bounded capacity intervention on a microservice architecture. What we can report
is narrower than what we set out to claim, and more useful for it.

The translation layer holds. A requirement becomes a bounded intervention under a
guarantee that is proved rather than measured, and adversarial evidence shows the
guarantee is not vacuous. Porting it to a second system exposed an implementation
defect that violated that very guarantee, which no amount of testing on the
original topology could have revealed --- a verified design still requires its
implementation validated where the accidental properties differ.

The guarantee also turns out not to be a stopgap. Holding the task and harness
fixed while replacing a lite-tier proprietary generator with an open-weight
$117$B model cut magnitude error $25{\times}$ and left gateway misdirection at
$92\%$. Capability and validity are separable properties of a generator, and the
kind of error that a verifier eliminates is not the kind that scale repairs. We
expect this to generalise beyond capacity analysis to any pipeline where an LLM
emits an object whose admissibility is defined by membership in a structure the
model was never constrained to respect --- a schema, a type system, a call graph,
an architecture. Where such a structure exists, it can be checked, and where it
can be checked, a proof is available that no benchmark score can supply.

The capacity model forecasts, but only on data containing a load signal, and
establishing that required an evaluation able to fail. Our own earlier results
passed every check we then applied while measuring nothing: a memory error of
$2$--$4\%$ that a constant predictor also achieves. Three independent properties
make the standard RCA benchmark unsuitable for this question --- no load
variation, no measurable confounding, and interventions applied at the wrong
layer --- and each was invisible until we looked for it.

On the causal side the two commitments usually defended together come apart. The
dependency graph earns its place. The $do$-operator does not, and the reason is a
property of the problem rather than of our design: a new customer-facing feature
enters at the system boundary, so the intervention necessarily sits at a root
node, where truncated factorisation removes nothing. That is also why the
microservice literature's causal machinery has been productive for retrospective
diagnosis, whose interventions are internal, and not for prospective forecasting.

None of this makes the framework a better forecaster than a regression. What it
offers is an interface --- a requirement in English becomes a bounded, auditable,
refusable intervention --- and a model behind it evaluated by a protocol that
would have told us had it been measuring noise. That last point may be the most
transferable: an evaluation which cannot return a negative answer will not.
