% ABSTRACT
% =========================================================
\begin{abstract}
When a new feature is requested during software maintenance, engineering teams must judge whether the architecture can absorb the resulting workload before implementation — a question usually answered by heuristic tuning rather than measurement, since an unbuilt feature has no telemetry. AIOps (Root Cause Analysis) diagnoses disruptions only after they occur; Structural Causal Models (SCMs), despite supporting $do$-calculus intervention, mainly explain past data rather than forecast unbuilt requirements. Neither paradigm bridges requirements engineering with prospective capacity planning, the missing link for shifting operational reasoning left. We introduce a framework combining a Guardrailed LLM Parser that translates natural-language requirements into bounded interventions $do(X{=}x)$, and a Dual-Path SCM that projects downstream resource impact. Grounded in the LLM-Modulo paradigm, the Parser acts only as a candidate generator, bounded by a 6-Guard topological, empirical, and taxonomy-membership verification system that refuses a numeric verdict for out-of-taxonomy requirements. Interventions propagate through a topology-adaptive, multi-tier DAG isolating network-layer workload propagation from hardware resource consumption (CPU, memory), via a queueing-inspired regressor for non-linear latency and cascade attenuation. We evaluate on two RCAEval testbeds of different scale (Sock Shop, 7 services; Train Ticket, 28), reporting per-system results since accuracy does not generalize uniformly across topologies. Across 3 independent live-LLM repeats, runtime guards drive boundary-violation, hallucination, and gateway-misdirection failure modes to exactly zero every time, while an unguarded baseline's own numeric error varies by over $6\times$ run-to-run. We report this transparently: the model's accuracy advantage on our smaller testbed does not transfer to the larger one; its value instead rests on $do(x)$ feasibility queries no regression baseline can answer.
\end{abstract}

% I. INTRODUCTION

\section{Introduction}
\label{sec:introduction}

The rapid adoption of microservice architectures has revolutionized cloud-native development. During ongoing maintenance, however, most new work does not originate from the engineering team itself but from an external \emph{requirement}: a customer request, a product-management ticket, or a design document describing a feature that does not yet exist in the running system. Before committing engineering effort, teams must judge whether the architecture can absorb the workload this requirement will introduce — a question that, by definition, has no historical telemetry to answer it directly.

Despite advancements in AIOps, current methodologies exhibit critical gaps for this setting. First, existing Causal RCA frameworks are inherently observational and retrospective, diagnosing incidents that have already occurred rather than ones a not-yet-built feature might cause. Second, SCMs theoretically support counterfactual reasoning; yet, applied research primarily uses them to solve $P(\text{Cause} \mid \text{Anomaly})$ rather than to project the effect of a hypothetical new requirement. Third, engineers lack a grounded way to turn a natural-language requirement into a quantitative workload assumption at all, relying instead on manual, heuristic estimation.

To bridge these gaps, our framework reframes microservice analysis toward prospective, requirement-level feasibility forecasting: given a natural-language description of a new requirement, project its downstream resource impact and a feasibility verdict \emph{before} implementation. By utilizing Pearl's $do$-calculus, we allow engineers to inject the counterfactual workload a requirement would introduce and observe its simulated propagation.

\textbf{Scope.} We deliberately bound ``new requirement'' to features whose workload behavior can be approximated by an existing calibration archetype within the target system's known request taxonomy (Section~\ref{sec:methodology}) — e.g., a new promotion mechanic is treated as a variant of an existing checkout-discount archetype rather than as an unprecedented category. This is consistent with how the framework is meant to be used in practice: as a decision-support tool for feature requests that extend an already-deployed system's existing request taxonomy, not as an open-ended predictor for arbitrary, never-before-seen application domains. A requirement that matches no known archetype closely is out of scope for a numeric verdict; Section~\ref{sec:discussion} discusses how the current implementation behaves in that case and what a scope-respecting implementation should do instead.

Our main contributions are:
\begin{enumerate}
    \item \textbf{Grounded Parameter Estimation via LLM-Modulo:} We introduce a Parser Agent constrained by a 6-Guard defensive system (topological gateway invariance, physical delta bounds, adjustment clamping, service-existence filtering, similarity-gated fine-tuning, and an out-of-taxonomy refusal check). Evaluated with a live LLM backend, the first five guards reduced three observed failure modes to 0\% in one run; the sixth guard makes the system decline to issue a numeric verdict, rather than silently guessing, when a requirement matches no calibrated archetype.
    \item \textbf{Modeling Cascade Attenuation:} We utilize a 28-node hierarchical SCM that disentangles network-layer propagation from hardware-layer consumption, tracking how workloads decay or amplify across call chains. Because this decomposition is causal rather than statistical, a projected change can be attributed back to the specific upstream services and tiers driving it, via the same Shapley-over-DAG machinery Budhathoki et al.\ \cite{budhathoki2022rootcause} use for outlier root-cause attribution, run here in the forward, interventional direction instead of the retrospective one — a capability a black-box regressor's point prediction does not have, regardless of its accuracy, though we find in Section~\ref{sec:rq6} that its reliability does not yet transfer cleanly across topologies of different scale. We further show that, without an explicit monotonicity constraint, this component can produce sign-inverted (physically implausible) predictions under extreme extrapolation, and we report a mitigation and its residual limitations.
    \item \textbf{Domain-Aware Causal Mechanisms:} We integrate a queueing-inspired regressor into the SCM's structural equations to model non-linear latency bottlenecks, and we evaluate its behavior both in- and out-of-the-training-distribution.
    \item \textbf{Cross-Topology Evaluation:} We evaluate the full pipeline on two independent microservice topologies of substantially different scale (7 vs. 28 services) using the same protocol, and report where conclusions do and do not transfer between them.
\end{enumerate}

\section{Background and Related Work}
\label{sec:background}

\subsection{From Retrospective RCA to Prospective Forecasting}
Traditional machine learning struggles with confounders because it fits an association between $X$ and $Y$ within the observed data distribution, not a mechanism that still holds once $X$ is deliberately changed. Pearl's SCM \cite{pearl2009causality} resolves this via the $do$-calculus operator, which asks what the system's own structural equations would produce under a hypothetical intervention rather than what value historically co-occurred with a similar-looking input.

\textbf{This is not merely a re-weighting heuristic; it is a distinct, provably well-defined mathematical object.} Pearl's Truncated Factorization Theorem \cite{pearl2009causality} states that for an intervention $do(X_i = x_i^*)$,
\begin{equation}
P(x_1,\dots,x_n \mid do(X_i{=}x_i^*)) = \prod_{j\neq i} P(x_j \mid pa_j)\Big|_{X_i = x_i^*},
\end{equation}
i.e.\ the interventional distribution is built from the \emph{same} conditional mechanisms $P(x_j\mid pa_j)$ a model already estimates for ordinary prediction, with the edges into $X_i$ severed rather than conditioned on. A regression baseline fit purely on observational data has no such operator available to it: its point estimate $\hat y = h(x)$ re-weights whichever $(X,Y)$ pairs happened to co-occur in training, and this need not equal $\mathbb{E}[Y \mid do(X{=}x)]$ whenever an unobserved confounder affects both $X$ and $Y$. This is a difference of \emph{kind}, not of degree: no amount of held-out point-accuracy on observational data closes it, because the associational and interventional quantities are provably distinct objects under confounding — exactly the setting RQ2's regression baselines are evaluated under, regardless of which model wins on MAPE. Because our pipeline possesses a fitted SCM rather than only a causal graph, answering a $do(x)$ query is further \emph{computationally trivial}: it reduces to forward simulation, rather than the finite sequence of do-calculus rule applications whose completeness — that a finite derivation exists whenever an effect is identifiable at all — Huang and Valtorta proved for Pearl's three inference rules \cite{huang2006complete}. We stress what this establishes and what it does not: a claim about the \emph{well-definedness} of the $do(x)$ operation given a correctly specified SCM, not a claim about how closely our fitted $f_j$ approximate the real system — that empirical question is separate, and RQ1, RQ2, and RQ6 report it honestly, including where the answer is unfavorable to our own model.

Frameworks that leverage SCMs for microservice diagnostics apply this structure in the retrospective direction: Budhathoki et al.\ \cite{budhathoki2022rootcause} formalize how to attribute an already-observed outlier to its upstream root causes by tracing which ancestors' noise terms deviated from their typical behavior along a known causal graph, apportioning credit with Shapley values — the same mechanism DoWhy-GCM \cite{blobaum2024dowhy} exposes as \texttt{attribute\_anomalies}. Our codebase implements this mechanism in a module separate from the Capacity Agent evaluated elsewhere in this paper, whose own bottleneck ranking currently uses a simpler fixed-threshold heuristic instead (Section~\ref{sec:rq6}). Our work runs this identical structural machinery in the opposite, prospective direction: rather than asking which past ancestor explains an outlier that already happened, we ask which downstream nodes a hypothetical $do(\text{Workload}=w)$ would push into outlier territory before that workload is ever applied to the real system. Formally, let $\tilde x := \mathbb{E}[X \mid do(\text{Workload}=w)]$ denote the counterfactual point obtained by forward Monte Carlo simulation through the fitted DAG (Section~\ref{sec:workload-propagation}); applying the same IT-score and Shapley machinery of \cite{budhathoki2022rootcause} to $\tilde x$ against the training-period baseline $P(N_j)$ yields $S(\tilde x) = \sum_j c^{Sh}_{\tilde x}(j)$. The substitution of a hypothesized $\tilde x$ for an observed $x^*$ is licensed by the same modularity property \cite{blobaum2024dowhy} the retrospective case already relies on: $do(X_k=x_k^*)$ only replaces the mechanism at node $k$, leaving the joint independence of $N_{j\neq k}$ intact regardless of whether $x_k^*$ was measured or hypothesized — the same graph, the same decomposition, run forward instead of backward.

\subsection{Neuro-Symbolic AI and LLM Verification}
Recent studies highlight that while LLMs possess exceptional semantic reasoning, they exhibit severe deficiencies in deterministic planning \cite{kambhampati2024}. Following the LLM-Modulo and symbolic-feedback frameworks, we position the LLM strictly as a candidate generator, relying on external architectural guardrails to enforce correctness and topological constraints. Our multi-agent orchestration follows the ReAct paradigm of interleaved reasoning and tool-acting \cite{yao2022react}.

\subsection{Benchmarks and Statistical Comparison}
We evaluate on RCAEval \cite{pham2024rcaeval}, a public microservice RCA benchmark providing fault-injected telemetry for both Sock Shop and Train Ticket topologies. For comparing multiple models across datasets we follow the non-parametric testing methodology of Demšar \cite{demsar2006}, using paired Wilcoxon signed-rank and Friedman tests rather than parametric tests, given the small number of independent services per system.

\section{Methodology}
\label{sec:methodology}

\subsection{System Architecture Overview}
The system is implemented as a four-node LangGraph state machine (Fig.~\ref{fig:architecture}) executed sequentially for every incoming requirement: \emph{(i)} \textbf{Parse Requirement} — the Parser Agent (Section~\ref{sec:parser-agent}) turns natural-language text into a bounded intervention $do(X{=}x)$; \emph{(ii)} \textbf{Map Impact} — the Architecture Agent performs a breadth-first traversal of the dependency graph from the injection gateway to determine the blast radius of affected services; \emph{(iii)} \textbf{Simulate} — the Capacity Agent projects downstream resource consumption along two paths, a fast per-service bivariate SCM and an accurate 28-node global DAG that propagates the intervention through both the cross-service workload tier and the local resource-consumption tier (Section~\ref{sec:workload-propagation}); \emph{(iv)} \textbf{Generate Report} — an LLM synthesizes the projected metrics, the Capacity Agent's bottleneck analysis, and a self-critique (``Devil's Advocate'') pass into a natural-language \texttt{FeasibilityReport}. Only the first and third nodes involve the causal/LLM machinery evaluated in Section~\ref{sec:results}; the second is a deterministic graph traversal and the fourth is a text-synthesis step not evaluated quantitatively in this paper.

\subsection{Parser Agent: Semantic Bridge and Verification}
\label{sec:parser-agent}
The Parser Agent translates natural language into a quantitative intervention vector $do(X=x)$. It follows a two-tier strategy: a deterministic keyword-similarity match against an empirical calibration table is attempted first (bypassing the LLM entirely when similarity $\geq 0.6$); otherwise the LLM is invoked to propose a request type, affected services, and a bounded adjustment. In both branches, the output passes through six runtime guards before being returned:
\begin{itemize}
    \item \textbf{(G1) Gateway Invariance:} enforces that the injection point $do(x)$ is applied at a node with in-degree $= 0$ in the dependency graph; if the LLM proposes an internal node, the system falls back to the nearest valid gateway and downgrades confidence to \textsc{low}.
    \item \textbf{(G2) Physical Delta Bound:} clamps the proposed workload delta to an empirically justified range $[5\%, 50\%]$.
    \item \textbf{(G3) Adjustment Clamp:} restricts the LLM's fine-tuning of the calibration anchor to $\pm 10\%$; violations are rejected and the system falls back to the unadjusted anchor value.
    \item \textbf{(G4) Service Existence Filter:} discards any proposed \texttt{core\_services} entry that does not correspond to a real node in the topology graph, preventing hallucinated services from propagating downstream.
    \item \textbf{(G5) Similarity-Gated Fine-Tuning:} when keyword similarity to the closest known request type is below 0.6, the LLM's adjustment is forced to zero, i.e. only the calibrated anchor is used.
    \item \textbf{(G6) Out-of-Taxonomy Refusal:} the LLM branch is explicitly instructed to always select the closest-matching known request type rather than decline (Section~\ref{sec:edge-of-scope}), so after it returns a choice we independently recompute keyword similarity between the raw requirement and \emph{that chosen type's own} keyword list. If this is exactly zero — i.e. neither the rule-based pass nor the LLM's own selection shares a single keyword with the input — we treat the requirement as outside the calibrated taxonomy: confidence is set to \textsc{refused} and \texttt{is\_out\_of\_scope} is flagged. The report-generation node checks this flag deterministically and short-circuits to an explicit refusal report instead of letting the downstream LLM synthesize a confident-sounding verdict around a fallback number (Section~\ref{sec:edge-of-scope}).
\end{itemize}

\textbf{Formalization (LLM-Modulo bounded projection).} Let $L : \Sigma^* \to T \times \mathbb{R} \times 2^V$ be the LLM's (non-deterministic) candidate generator, mapping a raw requirement $r$ to a proposed $(t, \delta, S)$ — request type, workload delta, and core-service set. Guards G1--G6 compose into a single deterministic \emph{bounded projection operator} $\Pi$ applied to every candidate regardless of $L$'s output distribution:
\begin{equation}
\Pi(t,\delta,S) = \big(G_1(\text{inj}),\ G_4 {\circ} G_5 {\circ} G_3 {\circ} G_2(\delta, adj),\ G_4(S)\big),
\end{equation}
with, e.g., $G_2(\delta) = \max\!\big(5,\min(50,\delta)\big)$ and $G_3(adj) = adj \cdot \mathbb{1}[\,|adj|\le 10\,]$. Because $\Pi$ is total and deterministic, the structural guarantees on its output — valid gateway, $\delta \in [5,50]$, $S \subseteq V$ — hold for \emph{every} input in its domain; they do not depend on whether $L$ hallucinates, only on $\Pi$ itself. This is precisely the LLM-Modulo separation of concerns \cite{kambhampati2024}: $L$ is a candidate generator of unconstrained reliability, and $\Pi$ is the sound, LLM-independent verifier. G6 differs qualitatively from $\Pi$'s other components: rather than projecting an out-of-range candidate back into a valid one, it detects when no projection can be trusted at all and substitutes an explicit refusal (Section~\ref{sec:edge-of-scope}) for a numeric verdict.

Separately, at graph-construction time, the dependency topology is verified to be acyclic (removing any residual cycle before it is used for simulation), which we treat as a structural precondition rather than a per-request guard. We note that one additional safeguard described in early design notes for this project — hard-clamping predicted resource values to $[0,100]$ — was \emph{not} implemented in the evaluated pipeline; Section~\ref{sec:discussion} discusses a concrete failure mode this gap causes and how we mitigated it at the causal-mechanism level instead. An additive-shift rule for simultaneous interventions on ancestor–descendant nodes was likewise never implemented; the pipeline evaluated here only supports single-intervention queries.

\subsection{Workload Propagation and Causal Simulation}
\label{sec:workload-propagation}
The Capacity Agent's accurate path models degradation using a two-tier DAG — 28 nodes on Sock Shop; Section~\ref{sec:rq6} evaluates a 112-node instance of the same construction on Train Ticket — fit with DoWhy's Additive Noise Model framework. The node set is partitioned $V = V_W \cup V_R$ into cross-service workload nodes and local resource nodes, with edges restricted to two kinds:
\begin{align}
\text{Tier 1 (workload):} \quad & W_j = f_j(PA_{W_j}) + N_{W_j}, \ PA_{W_j}\subseteq V_W, \\
\text{Tier 2 (resource):} \quad & R_j = g_j(W_j) + N_{R_j},
\end{align}
i.e.\ each resource node $R_j$ (CPU, memory, latency) has exactly one parent, its own service's workload $W_j$ — there are no $R \to R$ or $R \to W$ edges. This separation is what makes the per-node Shapley decomposition of Section~\ref{sec:background} \emph{potentially} interpretable as which tier is responsible for a projected change, not merely which node — Section~\ref{sec:rq6} tests this directly and finds it holds for Tier-2 (local) attribution but not reliably for Tier-1 (propagation) attribution, especially beyond Sock Shop's scale.

Resource-consumption mechanisms $g_j$ (CPU, memory) are fit as $g_j(w) = \boldsymbol{\beta}^\top w + \beta_0$ with coefficients constrained to $\boldsymbol{\beta}^* = \operatorname*{argmin}_{\boldsymbol{\beta}\geq \mathbf{0}} \lVert \mathbf{y} - X\boldsymbol{\beta}\rVert_2^2$ (non-negative least squares), which guarantees $\partial g_j/\partial w \geq 0$ and enforces a monotonically non-decreasing response to workload by construction (Section~\ref{sec:extrapolation}) — applied uniformly to both tiers, not only Tier 2. Latency mechanisms instead use a queueing-inspired regressor with feature transform
\begin{equation}
\phi(w) := \frac{w}{c-w}, \qquad c \approx 1.5 \max(W_{\text{train}}),
\end{equation}
fit as $R^{\text{Latency}}_j = \beta\,\phi(W_j) + \beta_0$, $\beta\geq 0$; as $w \to c^-$, $\phi(w)\to\infty$, approximating the heavy-traffic behavior $\rho/(1-\rho)$ of an M/M/1 queue as utilization approaches capacity $c$ \cite{kingman1961}, rather than a closed-form derivation from queueing theory.

\section{Experimental Setup}
\label{sec:setup}

\subsection{Datasets and Testbed}
We evaluate our framework on RCAEval \cite{pham2024rcaeval}: (i) \textbf{Sock Shop}, 7 microservices, 90 fault-injection scenarios (30 fault types $\times$ 3 runs), used for both the accuracy benchmark and a 90-run ground-truth direct-match validation; (ii) \textbf{Train Ticket}, 28 microservices (up to 384 recorded metric columns), 30 fault-injection scenarios (5 target services $\times$ 6 fault types, 1 run each). Both datasets share the same telemetry schema (per-service workload, CPU, memory, socket count, and $p50$/$p90$ latency, with an explicit fault-injection timestamp separating normal and faulty periods), and RQ1/RQ2 evaluate all three of CPU, Memory, and Socket on both systems (Tables~\ref{tab:rq1}, \ref{tab:rq1-gt}); Latency is excluded from the 4-model MAPE comparison on both systems for the reason given in Section~\ref{sec:workload-propagation} (standard regressors do not model its saturating behavior), not because of a schema difference between the two testbeds. To prevent pooled averages from obscuring subsystem- and topology-specific variation, we report results on a \textit{per-system} basis rather than a single pooled number.

\subsection{Baselines for Comparison}
\begin{itemize}
    \item \textbf{(B0) Rule-Only Parser:} a deterministic keyword-matching classifier with no LLM and no learned adjustment, used as the accuracy floor for requirement parsing.
    \item \textbf{(B1) Unguarded Zero-Shot LLM:} the same live LLM backend as our proposed parser, prompted directly with no calibration table and no runtime guards.
    \item \textbf{(B2) Unguarded Few-Shot LLM:} as B1, but with the system topology and calibration table given as in-context examples, still without any runtime guard.
    \item \textbf{(B3) Non-Causal Regression Baselines:} Linear Regression, Gradient Boosting Regression, and a Gaussian Process Regressor, trained and evaluated under the identical out-of-distribution protocol as the SCM (Section~\ref{sec:results}), used to test whether causal structure yields an accuracy advantage over standard regressors.
    \item \textbf{(B4) Uniform Delta Injection:} a naive propagation baseline that assumes every downstream service's workload changes by exactly the same percentage as the injected upstream delta, bypassing the dependency-graph propagation entirely.
\end{itemize}

\subsection{Evaluation Metrics}
We measure forecasting accuracy using MAPE, RMSE, and $R^2$, computed at full test-set resolution (i.e., on every held-out point rather than on quantile-bucket averages, which we found to substantially understate error \textemdash Section~\ref{sec:results}). For the Parser Agent we additionally report the Physical Boundary Violation Rate (PBVR), Service Hallucination Rate (SHR), and Gateway Misdirection Rate (GMR), plus mean end-to-end inference latency and the fraction of requests resolved without an LLM call (fast-path bypass rate).

\subsection{RQ2: Does Causal Structure Improve Accuracy Over Non-Causal Regressors?}
We compare the SCM against B3 (Linear Regression, Gradient Boosting, Gaussian Process) under the identical protocol, using paired Wilcoxon and Friedman tests on full-resolution MAPE, computed \emph{separately per metric} (CPU, Memory, Socket use incompatible units and cannot be pooled into a single RMSE-based test without inflating apparent significance).

On \textbf{Sock Shop} ($n=21$ service--metric pairs), the SCM is statistically significantly more accurate than Linear Regression when pooled across metrics ($p=0.0137$, median $\Delta = -0.94$ MAPE points, SCM lower), but is statistically indistinguishable from Gradient Boosting ($p=0.812$) and Gaussian Process ($p=0.421$). By win count, the SCM ties for first place (7/21 service--metric combinations), alongside Gaussian Process (7/21), ahead of Gradient Boosting (6/21) and Linear Regression (1/21).

On \textbf{Train Ticket} ($n=84$ service--metric pairs across CPU, Memory, and Socket — $4\times$ larger than Sock Shop), the result does \emph{not} replicate in the SCM's favor: the SCM wins only 11/84 combinations, the fewest of the four models (Gaussian Process 29/84, Gradient Boosting 27/84, Linear Regression 17/84). Pooled across metrics, the SCM \emph{is} significantly more accurate than Linear Regression here too ($p=0.00094$, median $\Delta=-0.14$), driven mainly by a large CPU-specific effect (median $\Delta=-9.72$, $p=0.0063$); but it is significantly \emph{less} accurate than Gaussian Process ($p=0.0192$, median $\Delta=+0.035$, negligible in absolute terms) and statistically indistinguishable from Gradient Boosting ($p=0.993$). The pattern that recurs on both systems — SCM beating the simplest baseline (Linear Regression) while failing to separate from the two more flexible ones — is consistent with the SCM's own mechanisms being close to linear-regression-equivalent in structure (Section~\ref{sec:workload-propagation}); we flag this rather than only reporting whichever $p$-value looks most favorable.

\textbf{We do not conclude that SCM point-accuracy is superior to standard regressors.} The advantage seen on Sock Shop does not transfer to Train Ticket. We interpret this as evidence that the framework's value should rest on its unique capability — supporting $do(x)$ intervention queries, which the regression baselines cannot answer at all — rather than on raw predictive accuracy, which we find is not stable across topologies of different scale.

This gap is not just a matter of degree, but of kind. A regression baseline, however accurate, returns a single scalar $\hat y$ with no internal structure: it was never given a causal graph, so it cannot say which upstream service or which tier (cross-service workload propagation vs.\ local resource consumption) is responsible for how much of that number — the question is not merely unanswered, it has no operator in a black-box model capable of asking it at all. The SCM's projection, by construction, \emph{can be} decomposed: the same Shapley-value machinery Budhathoki et al.\ \cite{budhathoki2022rootcause} use to attribute an already-observed outlier to its ancestors (Section~\ref{sec:background}) applies, run forward, to our projected $do(\text{Workload}=w)$ outcome. A structurally identical Shapley attribution mechanism is implemented in our codebase (\texttt{gcm.attribute\_anomalies}, run on interventional rather than observational samples) but is not yet wired into the Capacity Agent evaluated elsewhere in this paper, whose bottleneck ranking currently uses a simpler fixed-threshold heuristic instead; we report a validity check of this attribution mechanism, run in the interventional direction — including a controlled test of the tier-level decomposition specifically — in Section~\ref{sec:rq6}, and the result is mixed: reliable for attributing a change to the target's own local mechanism, unreliable for attributing it to upstream network propagation beyond Sock Shop's scale. We flag the distinction here as the structural reason $do(x)$ support is not a mere convenience feature — a capability no regression baseline has \emph{at all} — even though our specific implementation of the decomposition it enables is not yet uniformly trustworthy. The framework's other central claim — that runtime guards, not prompting alone, are what makes the LLM Parser usable — does not depend on this accuracy comparison; we evaluate it separately against baselines B0--B2 next.

Across 3 independent live-LLM repeats (temperature 0.2, non-deterministic), the unconstrained LLM (B1) misdirects the injection point away from the topology's gateway on \emph{every} prompt at \emph{every} repeat (GMR $=100.0\pm0.0\%$), hallucinates non-existent services on $91.3\pm1.2\%$ of prompts (SHR), and violates a stated physical bound on $38.0\pm2.0\%$ of prompts (PBVR); these structural failures compound into a mean anchor-value error (Anchor MAE) of $844.6\pm568.2\%$ of the true value (per-repeat range: $188.5\%$--$1173.4\%$) — the mean alone is roughly $3\times$ the figure a single earlier run of this same configuration had suggested. This mean is itself right-skewed, as in RQ1: the per-repeat \emph{median} error is far lower ($22.8$--$30.0\%$), and the inflation comes from only 2--3 of the 50 prompts per repeat where the unguarded LLM's output goes wildly out of bound — most strikingly an adversarial prompt describing a ``DDoS attack via millions of fake promo-code requests,'' which the unguarded LLM answers with a literal $50{,}000\%$ workload delta. Adding in-context calibration (B2) — the same live LLM, now given the system topology and calibration table as few-shot examples, still with no runtime guard — closes most of the gap on two of the four metrics (SHR $91.3\%\to2.0\pm0.0\%$, Anchor MAE $844.6\%\to38.6\pm0.2\%$) but leaves the other two largely unresolved: GMR only falls to $84.7\pm1.2\%$ and PBVR only to $14.7\pm1.2\%$, both consistently across repeats. In other words, better prompting alone still misdirects the injection point away from the gateway on roughly four out of five prompts, every time we ran it.

This is the concrete case for enforcement over prompting. Only the runtime-guarded configuration reaches $0.0\pm0.0\%$ on all three structural failure modes (PBVR, SHR, GMR) — exact-zero variance across all 3 repeats, not a single fortunate run — with an Anchor MAE ($2.4\pm0.2\%$) that matches, and slightly improves on, the deterministic Rule-Only floor (B0, $2.8\pm0.0\%$) — despite still invoking the LLM for 66\% of prompts (the fast-path bypasses it entirely for the remaining 34\% via deterministic keyword match, which also reduces mean latency relative to the always-LLM configurations). Because B2 already sees the same calibration table the guards check against, the residual B2$\to$Guarded improvement (GMR $84.7\%\to0.0\%$, PBVR $14.7\%\to0.0\%$) is not explained by additional information reaching the model; it isolates the marginal effect of \emph{enforcing} a topological/physical bound post hoc from the marginal effect of merely showing the model that bound as context, and shows enforcement — not context — is doing most of the remaining work, which is the motivation for the 6-Guard architecture over prompt engineering alone. \textbf{Caveat on GMR specifically:} Sock Shop has a single valid injection gateway (\texttt{front-end}); the evaluated Guarded configuration injects there directly rather than asking the LLM to propose an injection point at all, so its GMR$=0\%$ reflects this architectural choice, not G1's fallback branch (Section~\ref{sec:parser-agent}) catching and correcting a misdirected LLM proposal — a single-gateway topology never exercises that branch. PBVR and SHR, by contrast, do operate on the LLM's own delta and core-service outputs (via G2/G3 and G4 respectively) and are not subject to this caveat.

\subsection{RQ6: Does Interventional Shapley Attribution Correctly Localize Impact?}
\label{sec:rq6}
Section~\ref{sec:background} and Section~\ref{sec:results} (RQ2) argue that the framework's real advantage is not point-accuracy but that a projected $do(x)$ outcome can be \emph{decomposed} — attributed to specific downstream services and mechanisms — via the same Shapley-value machinery Budhathoki et al.\ \cite{budhathoki2022rootcause} use for outlier root-cause attribution, run forward instead of backward. This capability is implemented (\texttt{gcm.attribute\_anomalies} on interventional samples, in a module separate from the Capacity Agent evaluated elsewhere in this paper) but had not been checked for basic trustworthiness before this RQ. We run four validity checks — three on Sock Shop's 28-node DAG (one shared with Train Ticket), one on Train Ticket's larger graph; none requires the LLM API, so all four are unaffected by RQ5's quota exhaustion.

\textbf{Null-condition false-positive rate.} We run $do(\text{front-end\_workload} = \bar{w}_{\text{train}})$ — i.e.\ no real change — 20 independent times (Monte Carlo draws differ only by seed) and check how often the existing risk-level heuristic (a fixed percentage-change threshold, or an IT-score threshold from \texttt{gcm.anomaly\_scores}) flags a node "warning" or "critical" anyway. \textbf{This uncovered a real calibration bug}: at $85\%$ scenario-level (i.e.\ at least one false alarm in 17/20 runs), concentrated almost entirely in one node (\texttt{catalogue\_cpu}, flagged in 85\% of runs). The cause is a small-denominator artifact: \texttt{catalogue\_cpu}'s baseline value is small (${\sim}0.23$ in its native units), so a purely Monte Carlo absolute deviation reads as a percentage swing as large as $+118\%$ under a condition with no real change at all. We fixed this by requiring every risk-level trigger — both the percentage-change path and the IT-score path — to also clear a z-score gate ($|{\text{predicted}-\text{baseline}}| / \sigma_{\text{train}} \geq 1$ for warning, $\geq 2$ for critical), computed against each node's own training-period noise rather than a fixed cross-node number. A first fix that gated only the percentage path reduced the false-positive rate to $65\%$; gating the IT-score path as well eliminated it, at $0.0\%$ across all 20 repeats. We report both the bug and the two-step fix rather than only the final number, since the intermediate result shows the bug was not a single trivial typo.

\textbf{Dose-response monotonicity.} For the node most directly downstream of the injection point (\texttt{front-end\_cpu}), we ran 5 independent repeats at each of 5 intervention levels ($0\%$ to $+300\%$) and computed the Spearman correlation between intervention magnitude and (i) the raw IT-based anomaly score and (ii) the Shapley contribution, across three independent executions of this exact experiment (before and after the calibration fix above, which does not itself change either quantity — only which repeats it retroactively would have flagged). \textbf{The two diverge sharply.} Shapley contribution's correlation with intervention magnitude was stable and strong across all three runs ($0.90$, $1.00$, $1.00$) and, in the post-fix run, translates into a sensible decision boundary: $0$--$20\%$ load stays \textsc{normal}, $50\%$ consistently triggers \textsc{warning} ($z\approx2.0$), and $150$--$300\%$ consistently triggers \textsc{critical} ($z\approx6$--$12$), with zero false alarms at $0\%$ across 5 repeats. The raw anomaly score's correlation, by contrast, was unstable and at one point \emph{negative} across the same three runs ($-0.50$, $0.50$, $0.60$) — it is not reliably monotonic run-to-run. \textbf{We flag this explicitly}: the Shapley-based attribution this paper's central value proposition rests on behaves like a trustworthy signal under these checks, but the raw per-node anomaly score it is partly built from does not, and should not be read as validated by this result.

\textbf{Topology respect (Train Ticket).} Sock Shop's 7-service graph is too small and too densely reachable from its single gateway for a clean negative-control test — nearly every node is downstream of \texttt{front-end}. Train Ticket's fitted accurate-path DAG is not: from the natural gateway \texttt{ts-preserve-service}, 17 of the 27 other services are reachable (hops 1--3) and \textbf{10 are genuinely unreachable} (no path exists in the fitted graph at all), giving a principled test — attribution should not meaningfully favor unreachable services over reachable ones. We intervened at $+150\%$ for 10 independent repeats and ranked all service CPU nodes by Shapley contribution each time. \textbf{The result is negative}: Precision@17 (the fraction of the top-17 Shapley-ranked services that are genuinely reachable) was $60.0\%$, statistically indistinguishable from the $63.0\%$ expected by topology-blind chance alone; mean Shapley contribution was in fact slightly \emph{higher} for unreachable services ($0.179$) than for reachable ones ($0.143$). The raw magnitude of predicted change did point the right direction (reachable services showed a larger mean $|\text{change\_pct}|$ than unreachable ones, $6.9\%$ vs.\ $3.9\%$), but this signal was too weak relative to Shapley's noise to produce a topology-respecting ranking.

We had one specific, testable hypothesis for this result: the Train Ticket DAG used here, fit by the Capacity Agent's own \texttt{train\_accurate\_path()}, lacked the non-negative-coefficient (monotonicity) constraint the Sock Shop DAG used in the two checks above already had on its Tier-1 workload-propagation edges. \textbf{We tested this directly rather than only flagging it}: we applied the identical constraint used for Sock Shop to Train Ticket's Tier-1 and Tier-2 mechanisms alike (Section~\ref{sec:extrapolation}) and re-ran the exact same check. Precision@17 moved from $60.0\%$ to $60.6\%$ — statistically unchanged, and mean Shapley contribution remained higher for unreachable services ($0.169$) than reachable ones ($0.125$). \textbf{This rules out the monotonicity-fit confound as the explanation}: the negative result is not an artifact of Train Ticket's DAG being fit less carefully than Sock Shop's — the two are now fit identically, and the gap persists. We therefore report this as a genuine, unexplained negative result on Shapley attribution's reliability at Train Ticket's scale (112 fitted nodes vs.\ Sock Shop's 28), and leave identifying its actual cause — Monte Carlo approximation error at this graph size, or confounding shared across services independent of the fitted causal edges — as the next diagnostic step (Section~\ref{sec:discussion}) before trusting this mechanism beyond Sock Shop's scale.

\textbf{Tier-1 vs.\ Tier-2 decomposition.} Sections~\ref{sec:workload-propagation} and~\ref{sec:results} (RQ2) make a more specific claim than either check above tests: that Shapley attribution can decompose a projected change at one target node into how much comes from Tier-1 network propagation versus Tier-2 local resource conversion. Neither the dose-response check (whose target, the injection node itself, has no Tier-1 ancestor to separate from) nor the topology check (which compares totals \emph{across} services, not tiers \emph{within} one) actually exercises this. We test it directly with a ground-truth-by-construction design: for each of several downstream targets, we construct a \emph{Tier-1-driven} anomaly (a real $do(\text{gateway\_workload} = 2.5\times)$ intervention, target's own value left to the fitted mechanism) and a \emph{Tier-2-driven} anomaly (no real workload change, but the target's own resource value manually perturbed by $+5\sigma$ — simulating a local inefficiency independent of traffic). \texttt{gcm.attribute\_anomalies} returns a per-ancestor contribution dict that already separates every \texttt{*\_workload} ancestor (Tier 1) from the target's own key (Tier 2); we check whether the tier with the larger $|{\text{contribution}}|$ matches the known true cause, over 10 independent repeats $\times$ 6 Sock Shop targets and 10 repeats $\times$ 4 Train Ticket targets.

\textbf{The result is asymmetric and, on Train Ticket, poor.} Tier-2 (local) attribution is essentially perfect on both systems — $100.0\%$ accuracy, 120/120 and 80/80 trials. Tier-1 (propagation) attribution is unreliable even on Sock Shop ($60.0\%$, 36/60) and \emph{worse than chance} on Train Ticket ($17.5\%$, 7/40) — a $-32.5$ percentage-point gap from a 50\% coin flip, meaning the mechanism actively mis-attributes network-driven anomalies to the target's own node more often than it gets them right at this scale. The Sock Shop failures are not uniform across targets: direct children of the injection gateway (\texttt{carts}, \texttt{orders}, \texttt{user}) score $100\%$, while two-hop descendants reached only through an intermediate service (\texttt{payment}, \texttt{shipping}, both parented by \texttt{orders\_workload} rather than \texttt{front-end\_workload} directly) score $0\%$ — the mechanism appears to lose the propagation signal specifically across an intermediate hop, not uniformly. \textbf{We revise our claim accordingly}: attributing a resource anomaly to the target's own local mechanism is a validated capability; attributing it to upstream network propagation, at more than one hop or beyond Sock Shop's scale, is not — and Sections~\ref{sec:workload-propagation} and~\ref{sec:results} should be read with this asymmetry in mind rather than as a uniformly validated tier decomposition.

% VI. DISCUSSION & THREATS TO VALIDITY

\section{Discussion and Threats to Validity}
\label{sec:discussion}

\subsection{The Extrapolation-Sign Failure Mode}
\label{sec:extrapolation}
During development we found that, at large synthetic interventions (e.g., $do(\text{workload}) = +150\%$ or $+300\%$), the resource-consumption mechanisms could predict a \emph{decrease} in CPU or memory usage in response to an \emph{increase} in workload — a physically implausible sign inversion caused by unconstrained linear extrapolation compounded across the two-tier graph. This is precisely the failure mode that a hard $[0,100]$ output clamp (an early design goal, see Section~\ref{sec:methodology}) would have masked rather than fixed. We instead constrained every workload-propagation and resource-consumption mechanism to non-negative coefficients, which enforces monotonicity by construction; this reduced, but did not eliminate, sign-inverted predictions at the most extreme interventions (roughly 7--19 of 56 service $\times$ scenario combinations at $+150\%$/$+300\%$, depending on the mechanism-fitting run). This constraint was originally applied only in the evaluation harness (used for RQ4) and not in the Capacity Agent that \texttt{orchestrator.py} actually runs end-to-end; we found and closed this gap while running RQ6 (Section~\ref{sec:rq6}), so the same non-negative-coefficient fit now applies uniformly to both. We flag every remaining case programmatically (an \texttt{extrapolation\_suspect} indicator) and exclude flagged points from any quantitative claim; results at $+150\%$/$+300\%$ should be read as directional illustrations, not as validated forecasts.

\subsection{Behavior at the Edge of the Declared Scope}
\label{sec:edge-of-scope}
Section~\ref{sec:introduction} bounds ``new requirement'' to features approximable by an existing calibration archetype. An earlier version of the evaluated pipeline handled this boundary poorly: when a requirement matched no keyword, the rule-based classifier silently fell back to a default archetype (the lowest-impact category in our taxonomy) with no ``no reliable archetype'' signal, and the LLM branch was explicitly instructed to always select the \emph{closest-matching} known archetype rather than decline — a deliberate anti-hallucination design choice (Section~\ref{sec:parser-agent}) that had the side effect of never reporting ``insufficient calibration data'' even when that was the honest answer. Both paths could therefore return a confident-looking numeric verdict for a requirement that shared nothing in common with the system's taxonomy.

We close this gap with Guard G6 (Section~\ref{sec:parser-agent}): after either path settles on a request type, we independently recompute keyword similarity against \emph{that type's own} keyword list; if it is exactly zero for both the rule-based guess and the LLM's own selection, the requirement is flagged \texttt{is\_out\_of\_scope} and the report-generation node deterministically substitutes an explicit refusal report (recommending manual load-testing) for the usual LLM-synthesized verdict — a code-level short-circuit rather than an instruction the synthesis LLM could smooth over. We verified this live end-to-end on two cases with the same LLM backend used in RQ3: an in-taxonomy requirement (``apply a 20\% checkout discount'') resolved normally at \textsc{high} confidence, while a genuinely unrelated one (``integrate a factory robot controller over CAN bus and Siemens S7 PLC'') triggered G6 even though the LLM itself, followed its instruction to always guess, had proposed \texttt{PLACE\_ORDER} as the ``closest'' archetype — confirming the guard does not rely on the LLM's own self-reported confidence, which in this case was already low but not reliably so in general.

Two related limitations remain. First, G6's zero-keyword-overlap criterion is coarse: a requirement that shares one incidental keyword with an unrelated archetype (e.g. mentioning ``order'' in an unrelated sentence) would not trigger it, so this is a floor on refusal recall, not a complete solve of taxonomy-membership detection. Second, a separate out-of-distribution confidence module exists in our codebase (percentile-based against the training distribution, described in the pre-mortem RCA design) but is not yet wired into this pipeline; the confidence reported end-to-end still reflects only text-parsing/taxonomy-membership certainty (G1–G6), not workload-\emph{magnitude} extrapolation risk — a familiar request type pushed to an extreme projected load will still receive a numeric verdict without the OOD caveats discussed in Section~\ref{sec:extrapolation}. Wiring that module into \texttt{generate\_report\_node} the same way G6 is wired is the natural next guard to add.

\subsection{Threats to Validity}
\begin{itemize}
    \item \textbf{Scalability.} Train Ticket telemetry contains up to 384 metric columns; per-node causal-mechanism fitting is currently independent and linear in the number of nodes, but the two-tier DAG construction scales worse and was not stress-tested beyond 28 services.
    \item \textbf{Interventional Shapley attribution is reliable for local (Tier-2) attribution but not for propagation (Tier-1) attribution, and the latter degrades further at Train Ticket's scale.} RQ6 found zero false positives and sensible dose-response on Sock Shop's small DAG, and $100\%$ accuracy attributing a locally-injected anomaly to a target's own mechanism on both systems — but ranking services by propagation reachability on Train Ticket's larger DAG (112 fitted nodes) was statistically indistinguishable from chance, and a controlled test attributing a real network-propagated anomaly to the correct tier scored only $60.0\%$ on Sock Shop and $17.5\%$ (worse than a coin flip) on Train Ticket. We tested and ruled out one specific hypothesis for the Train Ticket gap (that its DAG lacked Sock Shop's monotonicity constraint) by applying the identical constraint and re-running the check — the result did not change. The actual cause of the propagation-attribution failure remains open (candidates include Monte Carlo approximation error at this graph size, or attenuation of the propagation signal across intermediate hops — Sock Shop's own two-hop targets scored $0\%$ while its one-hop targets scored up to $100\%$), and the mechanism is still not wired into the Capacity Agent's own bottleneck ranking used elsewhere in this paper (which uses a simpler fixed-threshold heuristic instead).
    \item \textbf{Topology dependence.} Our approach depends on the accuracy of the extracted dependency graph; RQ2 shows that even accuracy conclusions, let alone graph structure, do not transfer between topologies of different scale, so results on a third topology cannot be assumed without re-running the full protocol.
    \item \textbf{Coverage of the Train Ticket evaluation.} We used 30 of the 90 available fault-injection scenarios (single run per fault type) to keep the exploratory evaluation tractable; the full 90-scenario protocol used for Sock Shop has not yet been run on Train Ticket.
    \item \textbf{Single-model LLM evaluation.} RQ3 uses one LLM backend (\texttt{gemini-flash-lite-latest}) across 3 independent repeats at temperature 0.2; the guarded configuration's failure rates were exact-zero at every repeat, but the specific failure rates and run-to-run variance of the \emph{unguarded} baselines may still differ substantially with other model backends, which we have not tested.
    \item \textbf{GMR is architecturally trivial on a single-gateway topology.} Sock Shop has exactly one valid injection gateway; the evaluated Guarded configuration injects there directly without ever asking the LLM to propose one, so RQ3's GMR$=0\%$ for our configuration does not exercise G1's fallback branch (Section~\ref{sec:parser-agent}). A topology with multiple candidate gateways would be needed to evaluate G1's corrective behavior itself rather than only its trivially-satisfied outcome on this benchmark.
    \item \textbf{Refusal covers taxonomy membership, not workload magnitude.} Guard G6 (Section~\ref{sec:edge-of-scope}) now refuses a numeric verdict for requirements outside the calibrated taxonomy, but a familiar request type pushed to an extreme projected load still receives one without an OOD caveat, since the percentile-based confidence module described in Section~\ref{sec:edge-of-scope} is not yet wired into the report-generation node; deployment as a decision-support tool should still treat any \textsc{low}-confidence or \textsc{warning}-level output (Section~\ref{sec:extrapolation}) as a prompt for manual load-testing, not as a substitute for it.
\end{itemize}

\subsection{Future Work}
Beyond the open items above (RQ5 single-agent baseline, full-scale Train Ticket run, a topology with more non-root services to further power RQ4, diagnosing RQ6's still-unexplained propagation-attribution failure at Train Ticket's scale now that the monotonicity-fit confound has been ruled out (Monte Carlo approximation error at scale and cross-hop signal attenuation are the leading remaining hypotheses), and wiring RQ6's Tier-2-validated (but not yet Tier-1-validated) attribution mechanism into the Capacity Agent's own bottleneck ranking), a natural next guard (G7) would wire the existing percentile-based OOD confidence module into \texttt{generate\_report\_node} so extreme-load requests receive the same explicit-refusal treatment G6 now gives out-of-taxonomy ones. Further out, we will explore dynamic graph updates under auto-scaling and an explicit statistical equivalence test (TOST) for the several RQ2 comparisons that fail to reject the null but should not be read as proof of parity.
